# The shell bridge

How VimStorm draws Abe's screens: component trees from `abe ui bridge`, its protocol, slots, layers and the look. The screens themselves: [the Board's](ui-board.md) and [Chat's](ui-chat.md).

## The bridge

ADR 0013 T3. VimStorm draws Abe's screens; TypeScript says what they are. `abe ui bridge` is a client of `serve` like any other tool, and VimStorm runs it as a child process (`app/src/factory`, the Factory view, ⌘⌥A from the Editor).

- **The tree** (`ui/src/runtime/components.ts`): a closed union of DS 2.0's components, each `{ kind, id?, props, children? }`: Island, Stack (`direction`, `gap`, `sizes`: `auto` · `{fixed: px}` · `{flex: n}` per child), ToolWindowHeader, ListRow (inline children after the text), Badge, KeyHint, AgentStatus, Empty. `Node.parse` refuses any other kind or prop; Rust draws an unknown kind as a dim `needs component: <kind>` box. Core knows a tree only as its wire shape (`core/src/contract/ui.ts`: `UiNode`, the outline text): core has no UI (ADR 0015).
- **A screen** (`ui/src/runtime/runtime.ts`) is pure: `step(screen, state, input) → { state, tree, commands }`. Inputs: `open`, `resize`, `key` (the app's nvim notation: `r`, `<CR>`, `<D-CR>`), `click` (a node's or header tab's `id`), `text`, `result` (a `run`'s `--json` answer, typed by the command table) and `event` (an `abe watch` event). Commands: `run` (`abe <argv> --json`; its answer carries the command's human `text` too), `shell` (an effect only the shell does) and `open` (another screen in the Factory view). Screens read only the CLI contract's types. Register one in `ui/src/runtime/screens.ts`.
- **`abe ui render <screen> [--page <page>] [--json]`** runs the screen against `serve` until it asks for nothing more and prints its tree (an indented outline: `Kind #id prop=value`, children under it). `settings` draws the Settings dialog (a layer, not a screen) as ⌘, opens it, on `--page` (`problems`, `logins-tools`) when given.
- **`abe ui bridge`** speaks newline-delimited JSON on stdio, `v` 2 (`ui/src/runtime/protocol.ts`; ADR 0036). App → bridge: `hello` (size, version), `open` (screen, params; the screen already open is not opened anew, it gets the `open` input on its state), `input` (key, click, text), `resize`, `window` (the view shown, `editor` | `factory`, and whether the window is active; sent at the start and on each change: see Fresh data). `run` (id, argv: an `abe` command run as the shown folder's, answered by `answer` (id, reply: the command's `{ok, data | error}`), the shell's own calls: Create Draft PR). Bridge → app: `tree` (screen, rev, tree; rev rises by one per tree sent, and a tree is sent only when it changed), `patch` (once the app holds the slot's tree: screen, rev, `base` the rev it applies to, `ops` keyed subtree changes in order, `ui/src/runtime/patch.ts`; the app answers one it can't apply with `again` (slot), and gets the whole `tree`), `layer` (the top layer, or null), `shell` (`view` editor | factory, `open-project`, `balloon`, `widgets`: the status bar's whole set (each with an optional `tooltip`, `view` editor | factory it shows on, `place` start (beside the mode badge) | end; a click is a `click` on `widget:<id>`), `status`: one line on the status line, `open-file`: a file at a line in the Editor, `cmdline`: Neovim's own, `surfaces`: what to hide, a role's (see Roles)) and `error` (`unsupported-version` for any other `v`, `bad-request`, `unknown-screen`). It follows `abe watch` from the start (starting `serve` when none answers) and, when the stream breaks, follows it again and opens the screen anew. IO in `serve/src/process/bridge.ts`.
- **Errors clear themselves** (the rule in `ui/src/runtime/errors.ts`, applied by the bridge to every error balloon a screen says, the shell's balloon host `app/src/popups/balloon.rs` counting the same time): an error said on a run's answer carries that run's `key`, and the same run answered ok later sends `drop-balloon` (its status line clears too); any other fades after 8 s and its reading time (30 s at most), or at the next key or click once up a second, a hovered balloon staying; only a refusal whose code needs you (`NEEDS_YOU`: a login, a policy, a box) `stays`, with its `action` (`Log in…` opens Settings › Logins & tools, `Retry` runs it again, `Boxes…` the Boxes tab; a click on it is `balloon:<key>`). Every error balloon goes to the shell's history (`app/src/popups/errors.rs`): the status bar's dim `⚠ N` lists them newest first with when and where (`where`: the screen). A cloud workspace's red RemoteState card retries by itself once the header's feed says its box came up.
- **The contract files** `packages/ui/contract/`: `schema.json` (the tree and both sides' frames as JSON schema), `trees/*.json` (one per screen state the tests cover, plus `gallery.json` with every prop), `unknown/needs-component.json`, `frames/*.json`. The shell's cargo tests read the same files. `bun run contract` writes them; `contract.test.ts` fails when they differ from the code.
- **Adding a component**: its type and schema in `components.ts` (and `KINDS`), or for a screen's own set in a module of their own that `components.ts` adds to the union (`board.ts`: `boardSchemas`, `BOARD_KINDS`), its draw arm in `app/src/factory`, `bun run contract`, a fixture that draws it, then use it in a screen. A new screen needs no Rust.
- **The clock**: a screen gets `tick` inputs (RFC 3339) on open and every `TICK_MS` (15 s) from the bridge, once from `abe ui render`; screens read time only from them.
- **Slots**: the bridge mounts one screen per slot, `main` (the Factory view's body), `chat` (the Chat column), `pane` (the bottom pane's tab), `review` (the Git Log's PR review, below) and `popup` (a screen over `main`'s: ⏎ on a Board card opens its `card` screen there, `from: board`; the app draws it centred, 76 % × 88 % of the view, the Board dimmed behind; while it is open `main`'s keys, clicks and `extent` go to it and the Board is told it lost the keys; an `open` in `main` (its Esc opens the Board again on the card) or the app's `close {slot: popup}` (the rail left the Board) closes it, the app told `closed {slot: popup}`, what it keeps kept for its next open). `open`, `input` and `resize` take an optional `slot` (absent: `main`, so every older frame means what it did), and a `tree` frame names its `slot` (absent for `main`); a screen's `open` command may name one too. Layers stay global: while one is up every slot's keys go to it, and a menu's `choice` goes back to the slot that asked. Events, ticks, `exit` and `browser` reach every slot's screen. The app's `focus {slot | null}` says which slot has the keyboard (each screen whose slot got or lost it gets `{kind: 'focus', focused}`), `caret {file, line, selection?: {from, to}}` (the Editor's caret, relative to the shown folder, debounced) goes to the `chat` screen as a `caret` input (`no-caret` when no file is open in the Editor: the caret is gone), and `project` carries `box` (a cloud workspace's) and `branch`. Rust: `FactoryView` keeps a tree per slot and one PTY per terminal key whichever slot holds it; `SlotView` (`app/src/factory/slot.rs`, `FactoryView::slot_view`, `open_in`) draws a slot's tree in the bounds its host gives it, with the keyboard. A key a slot's screen did not take (no layer, menu or card of its own open) comes back as the shell effect `unhandled {slot, key}`: an Esc in `chat` gives the keyboard back to the code (`ChatColumn::esc_not_taken`; torn out, the main window comes to the front), and before the screen is drawn the column takes Esc itself. The `chat` screen (`ui/src/chat/pinned.ts`) is Chat pinned to the shown workspace: the chosen `session` param (once ended, it gives way to a new session on its story that Chat had not read when it was chosen: a Retry run or Launch new agent… from anywhere; a Reopen keeps its id), else the story's newest session not ended, else its newest ended one; the story is the `card` param, else a session's in the shown folder (or box), else the branch's `card/<n>-…`; no story: `No story here`; no session: the 2.1 header (`#<n>` and the card's title, the empty rail `New ○ no session`) over Abe's head, `No session on #<n> yet` and the primary `Launch agent ⏎` with `⌘⏎ more` dim, centred (the Empty's `head` and `actions`); ⏎ launches (`--target local-sandbox` from the Editor), ⌘⏎ the launch menu, the header naming where ⏎ launches (`Local sandbox` from the Editor; elsewhere `serve.target` read per folder, `Local sandbox` or `Cloud`, none named until read, read again on its `settings.changed`); launched, here or anywhere (the Board, the Card page, the CLI: serve's `launch.started`), `● Launching…` (`Chat attaches once its Claude Code runs.`) until its session comes, a second ⏎ launching nothing; refused (`launch.ended`), no session again with why under it (`Launch refused: …`); a cloud launch's steps heard before its session is listed (`session.step`, `launchSeen`) list there with their times as a listed launch's do. In the Factory view the app opens it on the selected card (`{card, whose?, title?}` or `{card: none}`, from the Factory screen's whole-state `selected` effect: at once in Chat mode, the Board's tree waiting up to 120 ms for Chat's answer so both change in one frame, once the selection rested 300 ms in Terminal mode) and on the Editor's shown workspace again when the Editor is shown. `whose` with `card`: a teammate's card, read-only (`<whose>'s session` as the header's environment, `<whose>'s story` · `Assigned to <whose>: Chat launches only your own cards.`, no launch, no launch menu; a card no one has: `Assign to me and launch`, as the story dialog's primary, `card assign <id> me` beside the launch). A session pinned before keeps its rendered Chat (`kept`, by session id): going back to a workspace finds its folds, cursor and scroll as they were, its transcript read again. An open naming a session it has not read (one just launched) reads the sessions and runs again. It follows `factory.stage`, `session.state` and `session.subagent` in place as the Board does (`ui/src/live/live.ts`), reading the runs again only for a run it does not hold or a pull request that moved. It draws the rendered Chat (see below); Claude Code's TUI is the column's Terminal mode (`abe session attach <id>`, a box's `abe box attach <box> --session <id>`). It sends the `chat-session` shell effect `{session: string | null}`: the session it is pinned to unless that ended, said on every `open` once the sessions are read and whenever it changed (a Retry run's or Launch new agent…'s new session at once); `FactoryView` keeps it (a restarted bridge opens Chat on it); the Editor's pinned Claude Code tab it fed is gone (3.0). `pipelines` is the pane's Pipelines tab (see The Pipelines tab).
- **Where commands run**: the app names the shown project's folder in `hello` (`root`) and as a `project` frame when another project is shown; the bridge runs every screen's and Command mode's command with that folder as its cwd, and gives it to the screen as its `root` open param (`--repo`).
- **The header** (B Signal, boards H-EditorB / H-FactoryB / H-States): the factory screen sends the `workspaces` shell effect (whole-state, sent only when it changed), `{workspaces, factory, answering}`: per story workspace (`ui/src/board/workspaces.ts`, the newest card session per worktree or box, its run's `lookOf` and rail) `{root, box?, story: {id, short, title}, state, dot, stage, rail, since, cloud, cloudHue, pr, branch, tab, tooltip, line, label, crumb, caption}`, the Factory view's `{line, label, crumb}`, and whether `serve` answers. Rust (`app/src/factory/workspaces.rs`) matches open projects to it (a cloud one by its box, a local one by its folder; none while down) and draws the strip's tabs (dot, `#id short`, 2 px StageRail, 12 px cloud, the selected tab tinted 10 % of the dot's hue), the toolbar's context line as badges (a click opens Linked as ⌃L does, a `jump` from the toolbar; the Factory line's Needs you `toolbar:needs-you`, which lands like `widget:factory`; `abe serve not answering` dim), the tree's root row, the status bar's story crumb (Factory view: its crumb and widgets only, never a branch) and the empty editor's caption. A project no entry names (the main checkout, or one not known yet) shows its folder's name, or the story a worktree's or box's branch names, with no dot.
- **The jumps and Linked** (2.1; boards W-Linked, Keys): the app sends `jump {to: workspace | story | linked, from: {place: main | chat | pane | editor | tree | git | toolbar | other, view}}` for ⌃W ⌃L, never from an nvim split or a PTY for the plain keys (there ⌃⌥W ⌃⌥L; Rust `app/src/workspace/projects/jumps.rs`). The bridge asks what is linked (`ui/src/board/jumps.ts` `storyOfJump`: the layer up's `LayerScreen.linked`, else the slot with the keys' `Screen.linked`, else the shown workspace's story from the header's feed or its `card/<n>-…` branch) and hands the jump on: Command mode first (⌃L opens Linked there, ⌃W closes every layer, drafts kept), then the Factory overview in `main` (Open story the story dialog over the view, `card show` for a story the board does not list; ⌃W the story's newest session's `workspace attach-spec`, after the sessions are read, landing as `open-project {chat: true}`: the Chat column on that session, the keys in the editor; a box not known to run opens Chat on `{session, waking}`); nothing linked: `Nothing linked here`. **Linked** (`ui/src/linked/linked.ts`, its node `LinkedLayer` in `linked-layer.ts`, Rust `app/src/factory/linked.rs`: Search Everywhere's 670 px, 48 px from the window's top) opens at once on its ten rows `Reading…` and reads `abe story linked <id> --part <part>` for each part (card, run, spec, pr, pipelines, box; serve shares one runs and sessions read among them while no event came since it started, `sharing`; the card is read in its run's checkout, `checkoutOf(run)`, as a card worktree's own settings may name no board), each part's rows drawn as it lands and the others kept (`mergeLinked`), so none waits for the slowest; an event reads the parts it can change again, one run of a part out at a time (an event meanwhile reads it once more after), and an answer asked before an event never draws over a row the event moved or a later answer drew (`LinkedLayer.drawn`); typing filters (every letter, `k l ö ä` too), ↑ ↓ ⌃N ⌃P move, ⏎ opens a row (`opensOf`: a jump, `open-url`, `open-file`, `view` + `open factory {card[, sheet]}`, `open chat {session} slot chat` + `show {place: chat}`, `open pipelines|boxes slot pane` + `show {place}`, a pick of several sessions or Sheets as menu rows that `do` their commands), and follows `abe watch` and the clock: Command mode gets `tick` and `event` too. The card's ⌘⏎ menu has Open workspace ⌃W · Open story · Linked ⌃L. `?` in the Factory view (not while its screen types: `Screen.typing`) is the key help (`ui/src/command/keys.ts`: this view's keys, `??` every key). The `g` jumps are gone.
- **Text fields** (`ui/src/runtime/field.ts`): every field the bridge draws (Command mode's filter and prompt, a pick's filter, the CommentBox, Chat's composer, a question card's own words, the Override reason, the `/` filters of the Board, Boxes and Sessions) keeps its text and a caret, and takes a macOS field's keys once there (`fieldKey`): ← → a character, ⌥← ⌥→ a word, ⌘← ⌘→ the start and end (the line's, in the CommentBox and the composer; Home End too, except where a list is under the field: there they move the list), ⌫ ⌦, ⌥⌫ ⌥⌦ a word, ⌘⌫ ⌃U to the start; no selection; ⌃W stays the jump. A frame carries it as `caret` (characters; absent: at the end); Rust draws it there (`app/src/factory/field.rs`), the header notes as `▏` in the text (`withCaret`). Linked's speed search and the Settings dialog's fields keep their own.
- **Layers** (`ui/src/runtime/layers.ts`: PickLayer, PromptLayer and ConfirmLayer are of the set too, but go as the bridge's own `layer` frame (`{v, type: 'layer', rev, tree | null}`, `rev` counted with the trees'), drawn by `app/src/factory/layers.rs` over whichever view is shown, the Editor too; while one is up every key, click and text goes to it, and `blur` (the view lost the keyboard: a click elsewhere, the view hidden) closes it. Their state (filter, cursor, focus) is TypeScript's; a click names a pick row's `id`, a confirm's `risky` or `no`.
- **Themes and the look** (2.1): `core/src/theme/theme.ts` holds the DS's 260 colour tokens in six groups (`theme-tokens.ts`), the built-in Islands Dark / Islands Light (`theme-built-in.ts`, `{token}` aliases), theme files `themes/<slug>.json` (`{name, base, tokens}`, only changed tokens, yours; `ports/src/mac/themes.ts` reads them) over a base, `planThemeSave` (a built-in is never written: `<Base> (yours)`) and `lookOf` (settings `ui.theme`, `editor.scheme`, `ui.density`, `ui.font.*` + an optional stage → `Look`: every token resolved (a named editor scheme's `SCHEME_GROUPS`, editor · git · diff · terminal, over the theme's chrome; `scheme` names it, nvim's `background` and mapping are its), density, fonts, `staged`, and `theme.syntax`, the base built-in's capture mapping: `darcula`, or Dark Modern's `vscode`, which `nvim/colors/darcula-contrast.lua` follows: every function name in the function colour, type names and primitives in the type colour). `abe theme list|show|look|save` (`serve/src/theme/theme.ts`; a theme file's change is `settings.changed`): list shows each slug beside its name, show and save take either (`findTheme`); save refuses to write over another theme of yours (`theme-exists`) unless `--replace`, and says what it replaced (the dialog's OK passes `--replace` and says so); a colour that is none is said per token (`frame-bg: red is not a colour like #b589ec`). A `ui.theme` no theme has is refused by `settings set` and a stage (`bad-stage`), each naming the themes there are; written in a Layer, it draws Islands Dark and is a `settings problems` row (`unknown-theme`, fix `abe theme list`). The bridge sends the `look` shell effect (whole-state) at start, on `project`, on `settings.changed` and after a reconnect, and again for a screen's `{kind: 'look', stage}` command (the Appearance / Colours pages' live preview; `null` drops the stage). The app applies it (`app/src/look.rs`): `theme.rs`'s runtime palette, density, fonts, the terminal's colours, nvim's highlights (`config/app/look.lua`).
