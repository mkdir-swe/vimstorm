# Boxes

A repo's box and its workspaces, the images, a new abe on the boxes, and the local `serve` that fronts your boxes. Setting one up: [Cloud](../cloud.md).

## The workspaces on a box

A repo's box holds a **box workspace** per card (ADR 0022). A `serve` started with `ABE_BOX=1` (the box's service) is the box's: `abe workspace up --repo <owner/repo> --card <id> [--title …]` makes the card's workspace or brings it back (run again it changes nothing, unless a newer workspace image is waiting and nobody is attached and no session runs: then the container is made again on the same volume), `abe workspace up --all` brings every workspace on the box back as its labels say (the box's startup runs it on every start; one that fails is said and the rest still come back), `abe workspace status` lists them, and `abe workspace rm <card>` removes one (its container, clone volume, database and socket folder; refused `unpushed` while its clone holds uncommitted or unpushed work, `workspace-busy` while a session runs or a terminal is attached; a Done run's clearing on the box runs it in place of removing the worktree). A 2.2 box's one workspace (`abe-workspace`, database `workspace`, socket folder `workspace/`: an **old box**) is still recognised under its old names. Which container a card's work is in is read from Docker's labels (`WorkspaceDirectory`); the box serve's session runner goes to the session's card's container by the session's id (`<card>-<4 hex>`, `cardOfSession`), its git, run tree and transcripts by the run's or session's card (`ByCard`, `serve/src/box/box-routes.ts`), the browser is each card's own, and the pr stage's GitHub reads go through any running workspace's `gh`. `up`, and a box's `serve` started again with the workspace running (before it answers), log the container's `gh` in with the box owner's GitHub login (on stdin, `workspaceGhLogin`; a launch, which always runs `up` first, does not log in again), so the pr stage and the deploy poll have it without a session's launch. Rules in `core/src/box/workspace.ts`, the flow in `serve/src/box/workspace.ts`, through the Docker and Mirrors ports.

- Images: `images/build.sh` builds the core base image `abe-base:latest` (`images/base/Dockerfile`, the real `bun run build:linux` binary as its last layer; Neovim 0.12 with VimStorm's config, the repo's `nvim/` as the `vimstorm-nvim` build context (the release's `/opt/abe/nvim` on a box, `scripts/release.sh` packs it into `images.tar.gz`), its plugins, treesitter parsers and Mason servers installed by `images/base/vimstorm-warmup.lua` (the config's `config/warmup.lua`, as on a local machine)), labelled `abe.version` (a box's `/opt/abe/version`, else `packages/serve`'s) and `abe.hash` (the binary's sha256). On a box `workspace up` builds the base again the same way (`/opt/abe/images/base`, `$ABE_IMAGES_DIR`; the running abe baked in) when it is missing or its labels are not the installed abe's (`basePlan`), so an upgrade's base has what the new abe needs (the `abe-run` user); a build that loses the race to the tag against another build of the same release (the box boot's own `images/build.sh`) uses that one. `workspace up` builds the repo's workspace image (`abe-workspace-<owner>-<repo>:latest`) from its `.abe/session/Dockerfile` on the box's mirror, again whenever that folder or the base changes (`workspaceImageCurrent`); a new image means a new container on the same volume once nobody is in it (`imageCurrent` says whether it runs the newest).
- A workspace: container `abe-ws-<card>` (no capabilities, no new privileges, Chromium's seccomp profile, AppArmor's `abe-workspace` in Docker's docker-default's place: docker-default with its `deny mount` replaced by only the mounts Claude Code's sandbox (bubblewrap) makes, and /proc's `kallsyms`, `modules` and `keys` not readable (`images/box/apparmor/abe-workspace`, loaded on the box host at boot by `images/box/apparmor.sh` (the unit `abe-apparmor`, before Docker; on a host without AppArmor Docker applies none); label `abe.apparmor`, a container under another profile is made again once nobody is in it), its system paths unmasked (`systempaths=unconfined`: Docker's masks over /proc stop a session's jail mounting its own; label `abe.systempaths`, one made with the masks is made again once nobody is in it), 3 GB hard, 256 MB shm, CPU shared equally, on its own bridge network `abe-ws-<card>` so no other card's container is reached, started again by `up --all`), its clone on `card/<id>-<slug>` with `.scratch` in volume `abe-ws-<card>`, database and role `ws_<card>` in the box's one Postgres `abe-pg` (1 GB), reached over its unix socket on the shared volume `abe-pg-socket` (`DATABASE_URL` is `postgresql://ws_<card>:…@/ws_<card>?host=/run/postgresql`: Claude Code's sandbox lets a command reach no raw TCP, but unix sockets; `pg_hba.conf`, written on every `up`, admits `postgres` by peer only, as serve's `docker exec --user postgres`, each workspace's role only to the database of its own name (`local sameuser all scram-sha-256`) with its password (a 2.2 workspace made before the socket over TCP, made again once nobody is in it), and no one else: one card's database is never another's, `workspace-db.docker.test.ts` against a real Postgres), `ABE_WORKSPACE=<card>`, and `serve`'s socket for that workspace `<state>/workspaces/<card>/serve.sock` mounted read-only at `/run/abe` (connecting needs no write; each workspace mounts only its own folder). Each session's own socket is in `/run/abe/s/<id>/`, a folder only the session's user enters (0700, `sessionDirAccess`), so the script user `abe-run` never acts as a session. A request on that socket is the workspace's session: `abe status` names the workspace, and until sessions are scoped only `help`, `status` and `browser start|stop|status` are answered there; the client there never starts a `serve`.
- **Ports** (`serve/src/box/workspace-ports.ts`, rules in `core/src/box/box-ports.ts`): `abe workspace ports [--card <card>]` runs `portsProbe` in each running workspace (`docker exec`: `/proc/net/tcp` and `tcp6`, the dev range 1024 to 32767, LISTEN only; its clone's env example, whose auth callback to localhost fixes a port, as install's Read finds it) and answers each card's `ports` and `fixed` (a stopped one, or one whose exec fails, left out). `abe workspace relay <card> <port>` keeps a listener on the box's own `127.0.0.1:<free>` (one per card and port, reused; refused `no-workspace` unless it runs) whose every connection runs `docker exec -i <container> abe port pipe <port>` (`WorkspaceRelays`, `ports/src/docker/workspace-relay.ts`), so a server bound to the workspace's loopback is reached; dropped when the workspace is removed or stops, and when serve stops. `abe port pipe <port>` (client only, `ports/src/docker/port-pipe.ts`, short-circuited in `main.ts`) pipes stdio to `127.0.0.1:<port>` there (`::1` when refused; nothing listening: exit 1). Every `PORTS_EVERY_MS` (3 s) the box's serve looks again and says `workspace.ports` for a card whose ports changed (first look only when something listens; a workspace gone: empty once). Tests: `core/src/box/box-ports.test.ts`, `serve/src/box/workspace-ports.test.ts`, `ports/src/docker/port-pipe.test.ts`.
- Mirrors: `<state>/mirrors/repos/<owner>/<repo>.git`, fetched with git asking `gh auth git-credential`; a wake with GitHub unreachable comes back from the clone already on the box.
- `images/box/imds-block.sh` is the box host's rule against the instance metadata service (with IMDSv2 hop limit 1 in the box template). Locally, `images/fake-box/run.sh up <seed-dir>` runs a box in a container on OrbStack (a macOS socket does not reach a Linux container, so the box's `serve` runs on Linux too).
- **Box parity** (3.2.1; `core/src/box/box-sync.ts`, `serve/src/box/box-sync.ts`): at a cloud launch, and before each turn when something changed on the Mac (its files' sizes and times, its `HEAD`, the environments on) or a token or key is due, the Mac's serve sends the card's workspace, on stdin through `abe box attach … -- docker exec -i` (never an argv, never a log), what the person has locally: the `abe.yaml` and `.claude/skills` files they changed and have not committed (`git status` in the main checkout: changed, new, deleted), `.abe/settings.local.yaml` (without its aws profiles and TEST yes), the Abe env files of the environments on for agents (prod only while `agents.prod` is on), the access tokens Claude Code keeps on the Mac (its Keychain item, else `~/.claude/.credentials.json`) for the `sources:` the install checked (a token about to end renewed first by the Mac's Claude Code, connecting a session's way; never the refresh token), and each such environment's aws short-lived keys from its profile. In the clone a team file the Mac changed is written where it differs from the card's base (`HEAD`), read-only, held out of the card's commits (`--skip-worktree`; an untracked one by the sync's own block of the clone's `info/exclude`, written anew at each sync, so a file given back is seen again) and listed in `~/.abe/sync/locked`, which the jail binds read-only and the next sync gives back to the card; every other team file stays the card's own, writable and committed as usual (a card keeps its Verification pack on its branch; the clone's `info/exclude` keeps Claude Code's own `.claude/` files out of git, never `.claude/skills`, 3.2.2). Yours are 0444, the env files 0400; the tokens are merged into the box's Claude Code store under the Mac's key, so the box's session's server of the same definition is signed in, and the keys sit in `~/.abe/sync` (0700, hidden from every command, written by no file tool). `abe run <script> [--env <env>]` on a box hands the script that environment's synced Abe env file and aws keys on stdin (dev's when none is asked), redacted from what it says; one not synced (off for agents) is refused. `session run --sync` and, on a turn, `session sync` tell the box's serve the Mac's `abe.yaml` (its checkout's from then on), the sources checked, which Abe env files are there (the session is told of those alone) and the paths the Mac changed (no file tool writes them). A card's local worktree gets the same uncommitted team changes: a tracked file that differs skip-worktree'd, an untracked one held out by the worktree's own `core.excludesFile` (`extensions.worktreeConfig`; the person's own excludes kept first), never the shared `info/exclude`, so the main checkout still shows them. Nothing goes from the box to the Mac; it is gone with the workspace.
- Releasing for the boxes: see A new abe on the boxes below.

## A new abe on the boxes

#188. A box runs the abe its user data pins, the local machine the one built here, so they can differ; the local machine says so rather than letting commands fail as unknown.

- **Versions.** `scripts/version.sh` is a build's version: `packages/serve`'s and the commit, `2.2.0-1a2b3c4d`, with `-dirty` for a tree with changes (`$ABE_VERSION` when named). `scripts/build.sh darwin|linux` (`bun run build:darwin|linux`, which `install.sh` / `app/scripts/bundle.sh` and `images/build.sh` run) compiles it in as `ABE_BUILD_VERSION` (`serve/src/process/version.ts`); `abe status` says it, from source the package's alone. Each reply carries serve's (`Reply.version`; one from before none, then the client asks `abe status`): a serve of another build than the client's is said, the last line of `abe status`, a line on stderr on any other command (`serveVersionLine`; never with `--json`). serve also says which abe is installed now (`StatusData.installed`, the `installed` row of `abe status`; `installedAbe` in `serve/src/process/version.ts`: install.sh replaces the binary serve started from while it runs, so serve runs `<that binary> --version` again each time the file changes; from source none). The install's version line names both (`InstallView.versions`, its `line` from core's `installVersionsLine`), with “serve is older than abe: `abe serve stop` once no session is live” when they differ (`serveVersionNote`), as install.sh says, and the install's session is told so at launch, to tell the person. Raise `packages/serve`'s version for a new release line.
- **Locally.** `box list` / `box status` carry each running box's `abe` and, when it is another release than this machine's, `skew` (the Boxes tab's Release cell in `warn`); a command the box's abe has not got is refused `box-version` naming both versions (see Your boxes, `--on`).
- **The release** (an org admin, AWS profile `abe-tooling`): on a clean commit, `ABE_ARTIFACTS_BUCKET=abe-artifacts-<tooling account> abe/scripts/release.sh` builds the linux binary with that version in it and puts it, its `.sha256` and `images.tar.gz` (`images/`, `packages/serve/package.json`, the repo's `nvim/`) under `abe/<version>/` (written once; `--force` again), then, last, `abe/current` (the version, one line). It prints the version. `--no-current` puts a build without moving the boxes to it; to move them later, or back: `printf '%s\n' <version> | aws s3 cp - s3://abe-artifacts-<tooling account>/abe/current`.
- **The pin** is `abe/current` in the artifacts bucket: every box's `boot.sh` (the org Terraform's `terraform/modules/box-boot`) reads it on each boot and installs it when the installed abe differs. While it cannot be read (missing, refused, S3 not up yet: the aws error is in the boot log), or its build fails to fetch, check or unpack, the box keeps the abe it has; only a box with none installs the Terraform-baked `abe_version` (box-boot's default, which `terraform/modules/box` takes too). So a release needs no Terraform; bump `abe_version` only to change that fallback.
- **New boxes** get it on their first boot: `boot.sh` installs the pinned abe as `/usr/local/bin/abe` and `/opt/abe` (`/opt/abe/version`), restarts `abe-serve`, and `abe workspace up` builds the base and workspace images again (a running workspace is made again only when nobody is attached and no session runs).
- **A box that exists** installs `abe/current` on its next start (`abe box stop` / `start`, or its idle stop and the next wake) once its user data reads `abe/current`. A box launched before that (its boot log never says `abe/current`) keeps the user data it was launched with: a new template version does not reach it, and a developer's role may not change user data. An admin, once per such box, while nothing runs there: stop it, put the template's user data on it, start it (its boot installs the new abe; from then on a stop and start is enough):

  ```sh
  id=$(aws ec2 describe-instances --filters Name=tag:abe:box,Values=<box> Name=tag:abe:owner,Values=<owner> --query 'Reservations[].Instances[].InstanceId' --output text)
  aws ec2 stop-instances --instance-ids "$id" && aws ec2 wait instance-stopped --instance-ids "$id"
  aws ec2 describe-launch-template-versions --launch-template-name abe-box --versions '$Default' \
    --query 'LaunchTemplateVersions[0].LaunchTemplateData.UserData' --output text >user-data.b64
  # --attribute/--value takes the base64 as the template holds it; `--user-data fileb://` fails on aws-cli 2.27
  aws ec2 modify-instance-attribute --instance-id "$id" --attribute userData --value "$(cat user-data.b64)"
  # once decoded it is the template's: Content-Type: multipart/mixed …
  aws ec2 describe-instance-attribute --instance-id "$id" --attribute userData \
    --query UserData.Value --output text | base64 -d | head -n 1
  aws ec2 start-instances --instance-ids "$id"
  ```

  (or `abe box terminate <box> --yes` and `abe box up` again: work not pushed is lost). Then `abe --on <box> status` says the new version and `abe box list` shows no skew.

## Your boxes

(`serve/src/box/boxes.ts`, `serve/src/box/on-box.ts`, `core/src/box/box.ts`, `ports/src/aws/boxes.ts`; ADR 0021). The local `serve` fronts your boxes.

- **Boxes** (`ec2Boxes`, `ports/src/aws/boxes.ts`) is EC2 through the `aws` CLI as you: your SSO profile (`box.profile`, the environment's `$ABE_BOX_PROFILE` over it, a shell's `$AWS_PROFILE` only where no Layer names one; an expired login is said with its `aws sso login --profile`, no profile at all as `aws-profile` naming `abe settings set box.profile`), your boxes the instances tagged `abe:owner` with your GitHub login (`box.owner`, `$ABE_OWNER` over it, else `gh`'s). IAM decides (the org Terraform's `abe-developer-boxes`, ABAC on `abe:owner`): you make boxes only from the launch template with your own box role and a listed size, and start, stop and resize only your own; nobody but the lead terminates one. No token is read or kept by Abe.
- **Your environment from the Layers** (`core/src/layer/personal-env.ts`, `serve/src/process/app.ts`): `box.profile`, `box.region`, `box.owner` (yours alone), `stores.logs`, `stores.org` and `board`'s `azureConfigDir` fill what the local serve's environment leaves unset (`withPersonalEnv`: `AWS_PROFILE`, `AWS_REGION`, `ABE_OWNER`, `ABE_LOG_STORE`, `ABE_ORG_STORE`, `AZURE_CONFIG_DIR`) as it starts, from yours on this machine (never a repo's), before any port reads it; `abe box attach` / `forward` take them the same way. `abe settings set board.azureConfigDir <dir> --mine` writes your az folder for this repo (`board`'s field, yours for this repo alone, `null` takes it out). A variable set where serve started overrides its key, and `abe settings explain` says so (`from environment ($ABE_BOX_PROFILE)`, `explainedWithEnvironment`). A shell's `$AWS_PROFILE` (a work one, say) is never abe's over your Layer: `box.profile` is the `AWS_PROFILE` abe's own lookups (boxes, the login secret, the stores) run on, `$ABE_BOX_PROFILE` alone over it; with no Layer naming one the shell's stands, and explain says `($AWS_PROFILE the Layers name none)`. `box.region` keeps `$AWS_REGION` / `$AWS_DEFAULT_REGION` over the Layer. A change applies on serve's next start. A box's serve reads none of them: its unit's environment and tags are its own. With `serve.target: local` and no box profile named, `box list` is refused `boxes-off` (`BOXES_OFF`, the Boxes tab's `Boxes are off`) and no scan asks EC2. Tests: `core/src/layer/personal-env.test.ts`, `serve/src/box/personal-env.test.ts` (a bare `env -i` serve listing boxes over a fake `aws` with only a Layer).
- **Attach and forward** (ADR 0021; `ports/src/aws/eice-link.ts`, `eice-tunnel.ts`, `attach-loop.ts`, `serve/src/box/box-attach.ts`): the local machine reaches a box over SSH through the org's EC2 Instance Connect Endpoint (the org Terraform's `terraform/box/eice.tf`; the box SG takes tcp 22 only from it; `abe-developer-attach`). Each connection makes a fresh ed25519 key in a private temp folder (offered again for 45 s once its push succeeded, its file removed after 75 s), and `ssh`'s ProxyCommand is abe's own tunnel client, `abe box tunnel` (`main.ts` starts it without `app.ts`): it signs `wss://<endpoint>/openTunnel` with SigV4 in its query (`sigv4.ts`, the empty body's hash as botocore signs it; a refused handshake is logged by its HTTP status only, never the signed URL) on the person's SSO credentials (`aws configure export-credentials`, handed down in ssh's environment, never argv), pushes the key with `SendSSHPublicKey` while the tunnel opens, and pipes stdin and stdout as binary frames, waiting on input (no 50 ms poll). ssh gets the t50b spike's options (`ServerAliveInterval=2`, `ServerAliveCountMax=3`, `TCPKeepAlive=no`, `ConnectTimeout=5`, `ObscureKeystrokeTiming=no`, `IdentitiesOnly=yes`), `-F /dev/null`, host keys per instance in `<state>/box-known-hosts`. `abe box attach <box> --session <id>` (what the local machine's `abe session attach <id>` runs for a cloud session) runs the box's `abe session attach <id>` (`docker exec -it abe-workspace tmux attach-session` there), without one a login shell in its workspace container (`docker exec -it -u abe -w /workspace/repo abe-workspace bash -l`, as VimStorm's terminal tabs open it; while none answers there the box's own, said so; `-- bash -l` asks for the box's own), `-- <argv>` a command; a terminal is a reconnect loop (ssh again at once on exit 255, then every 0.5 s; a refusal the tunnel calls final, such as no right to the box, ends it; a stopped box is woken first), a `--` command without a terminal is tried again only before it started (the box writes a mark on stderr first, taken out again), so it never runs twice. `--shared -- <argv>` (VimStorm's `exec`) runs it as a channel on the box's one shared connection: an ssh ControlMaster (`-M -N -f`, `ControlPersist=600`) whose control socket is `<state>/mux/<box's hash>.<start>` (the folder 0700); a call on a live master (`ssh -O check`) reads no address, credentials or key, a round trip only. The master logs in through the same ProxyCommand with a key of its own, fresh as any connection's and never kept: sshd checks a key only at the login, so the channels after it need none. One at a time per box (a lock folder beside the sockets); a master that died (its socket left) or is near the tunnel's cap is taken out of the folder and the next call makes a new one; one that cannot be made leaves the call its own connection. `abe box forward <box> <port>` keeps `127.0.0.1:<local>` on the box's port until Ctrl-C (`BoxLink.forward`; a drop mended with a 0.5–4 s back-off, given up after 5 min without a connection). A box is one of yours (`abe:owner` your login: `$ABE_OWNER`, else `gh`'s), by its `abe:box` name or instance id, found through `Boxes`: a teammate's box, by name or id, is `no-box`; `$ABE_BOX_PROFILE` the AWS profile; attach and forward reach boxes on the running local serve's profile and region (`abe status`'s `boxAws`, asked without starting one, 2 s at most), never their own environment's, which VimStorm opened from the Dock lacks (no serve answering: their own), `$ABE_BOX_TUNNEL_MAX_SECONDS` a short tunnel cap for the cap check; `$ABE_SSH` and `$ABE_EICE_URL` the fake `ssh` and endpoint in tests (`testing/src/fake-eice`, `serve/src/box/box-attach.test.ts`).
- **Ports** (`core/src/box/box-ports.ts`, `serve/src/box/port-forwards.ts`, `ports/src/mac/local-port.ts`): a dev server in a box workspace opened on this machine, one forward per workspace and port (`box`, `card`, `port`; several workspaces on one box, each its own). `abe port list [--box]` asks each running box's `workspace ports` (The workspaces on a box) and says the forwards this serve holds and every other listening port, offered (a box that cannot say: `unread`); `abe port open <box> <card> <port>` (the box running, never woken) asks the box's `workspace relay` and keeps an ssh forward to it (`BoxLink.forward` with the wanted local ports, the first one nothing answers on at 127.0.0.1 or ::1 and that binds): the box's port when free, else the next of 20, said (`localhost:3000 was taken`), else any; a port the repo's auth callback fixes (the workspace's env example, as install's Read finds it) that port only, taken: `port-taken`, one run at a time, naming our forward that holds it; `abe port close` lets it go. Each move is `port.forward` (`opening`, `open`, `asleep`, `failed`, `closed`). Its box's `box.state` `stopping` / `stopped` lets the ssh go (`asleep`) and `running` opens it again, the same local port first; a forward that drops with the box still running is `failed`. While it holds one the local machine follows the box (`FollowReason` `forward`), so the box's `workspace.ports` merge here; a forward never keeps a box awake (Keep awake does). Offered only, never opened by itself. `abe box forward` stays the CLI's way to a box host's own port. Local mode has no boxes: the app runs on this machine. Tests: `serve/src/box/port-forwards.test.ts`, `ports/src/mac/local-port.test.ts`.
- `abe box up <repo> <card> [--title <t>]` makes or wakes the repo's box (placed as a launch is: refused `box-limit` at `limits.maxBoxesPerPerson`, running and starting boxes counted, stopped ones not; `box place --apply` queues instead), `box.state` `starting` then `running` once its `serve` answers; `abe box list` (each box's name, EC2 state, instance type, and a running box's workspaces and load from its own `abe status`; the Boxes tab draws each box with its workspaces under it, their disk, an old box marked ⚠ with only Download locally and Terminate…; ⏎ on a workspace row is `abe box attach <box> --card <card>`, its ⌘⏎ Remove workspace… runs `abe --on <box> workspace rm <card>`), `abe box status|start|stop <box>` (answered once EC2 says running / stopped; a stop keeps the disk).
- **Boxes tab data** (`core/src/box/box.ts`, `box-sizes.ts`, `serve/src/box/box-uptime.ts`): `abe box list --json` is `{boxes, queued}`; each box adds `launchedAt` (EC2's `LaunchTime`, reset on each start), `release` (the box launch template version, EC2's `aws:ec2launchtemplate:version` tag), `repo` / `card` / `title` (its tags), `serve` (`answers` / `silent` while EC2 says running, else null), `abe` (a running box's abe version from its own `abe status`) and `skew` (only when that is another release than this machine's, core's `abeSkewed`: `2.0.0-alpha.0` against `2.2.0-…`, not another commit of the same line: `demo-shop-3 runs abe 2.0.0-alpha.0, this machine 2.2.0-1a2b3c4d: commands newer than the box's abe fail there · update the box release (…)`, core's `abeSkewText`; the text `box list` puts `abe <version>` on each running box's line and the sentence under a skewed one) and `costToday` (`{usd, minutes, hourly, at}`: minutes up since local midnight from the local machine's `<state>/box-uptime.jsonl` times `BOX_HOURLY_USD`, eu-west-1 on-demand; `boxCostAt` grows it from the clock); `shutting-down` boxes are left out; `queued` lists the placements Queued for a box (`{box, repo, card, title, since}`). `abe box keep <box>` keeps a box awake (`IDLE_KEEPS` `awake`, waking it first) and `abe box sleep <box>` lets it sleep again (the idle time counts from then): set on the box's own `serve` in `<state>/box-keep.json` with the box's boot id, so a `serve` restart keeps it and a new boot does not; `abe box stop` takes it off first. A box's `serve` says `box.idle` `{box, idle}` when its `stopsAt` or `keptBy` changes (merged into the local machine's watch for followed boxes; the local machine's `box keep` / `sleep` says it otherwise). `abe box terminate <box> --yes` (risky) is EC2 TerminateInstances as you, `box.state` `terminated`; IAM's refusal (only a lead terminates) is `terminate-refused` `Terminate refused: only your lead can terminate boxes`. Tests: `core/src/box/box.test.ts`, `box-idle.test.ts`, `ports/src/aws/boxes.test.ts`, `serve/src/box/idle.test.ts`, `box-uptime.test.ts`, `boxes.test.ts`.
- `abe --on <box> <noun> <verb> …` (anywhere before `--`): `serve` sends the rest, word for word, to the box's `serve` over the link and answers with what its `abe` printed, exit code included; a command only a newer box knows still goes. A box on an older abe: when its `abe` says `unknown command`, `unknown flag` or `unexpected argument` for a command this machine knows, the local machine asks the box's `abe status` and, its version not this machine's, answers `box-version` (exit 1) naming both and what to do, ``demo-shop-3 runs abe 2.0.0-alpha.0, this machine 2.2.0-1a2b3c4d: `box keep` needs this machine's abe on the box · update the box release (abe/README.md › A new abe on the boxes)``, in the shape asked for (`--json` or not); the same for every command the local machine sends a box (`box keep` / `sleep`, a cloud session's `transcript`, `asks`, `answer`, messages, `session run`'s flags): `serve/src/box/box-version.ts` (`versionedLink`, around the `BoxLink`), words and the reading in `core/src/box/box-version.ts`. Chat on such a session says `Transcript not readable: <that> · ⌘4 Terminal mode`. A sleeping box is woken first (`box.state` `starting`, then `running`, cause `wake`) and its `serve` waited for. `watch` streams the box's own events, `session attach` names the `abe box attach` command. A box that does not get the command through is said as it stands, with the next step (core's `BoxReach`, `boxReachText`, exit 3 `box-unreachable`): `box X is stopped · abe box start X wakes it`, `is starting · 3 min · try again in a minute…`, `is running · serve not answering · 2 min · still booting? …` (counted from its boot until its serve answered here once, then from when it was first found silent; past 15 min up, or after it had answered: `abe box attach X -- journalctl -u abe-serve`, stop and start), `is running · cannot be reached: <the link's words> · …`; a link failure reads EC2 again first, so a running box is never told to wake. The endpoint's `Unable to connect to target` (nothing listens on the box's port 22: its sshd not up, every boot's first half minute) is the serve not answering, never the tunnel's words (`SSHD_DOWN` in `serve/src/box/boxes.ts`). The same sentence is `box status`'s second line (`reach`, `readAt` in its `--json`), `session list`'s note for a running box that did not answer (a line each), and the Boxes tab's State tooltip (a booting box's says it boots, see The Boxes tab). `box start` / `box up` on a box booted under 5 min ago whose abe is not this machine's add `woke` (`abeWokeText`): `X woke on abe A, this machine B: it stays on A unless the boxes' release (abe/current) is another, which its boot then installs a minute or two from now · abe box status X says which abe runs`. A cloud launch on a box booted under 3 minutes ago on another release than this Mac's asks its `status` again until it runs this Mac's line or those minutes are over (`awaitRelease`), so `session run` reaches the abe its boot installs. The EC2 Instance Connect link keeps only a running box's address (its state is read anew until it runs). `serve`, `login <tool>` and `ui` run here only. Only the local machine wakes a box, through `Boxes.start`.
- **Progress line** (`core/src/contract/progress.ts`, `serve/src/process/progress.ts`, `waited` in `serve/src/process/client.ts`): in text mode, a command that may wait (box commands, `box list`, `session launch`, `factory run`, `session download|move-to-cloud|send|stop|show`, anything `--on` a box) asks with `progress: true`; `serve` then streams `box.state`, `box.step` (`booting`: EC2 runs it, its serve not answering yet; `workspace`; `claude`, said by the local serve as a box comes up) and `session.state` as `WatchFrame`s, then the reply. A second after asking the client writes `demo-shop-3: starting (EC2 pending)… 0:04` on stderr: on a terminal one line redrawn each second and on each step, erased once answered; elsewhere a line per step. `--json` stays one document; a `serve` from before answers with the reply alone. `abe box forward` says at once what it opens. - **Merged**: with `serve.target` your environment, `session list` asks every running box and tags each session with its box (a box's own answer replaces the local machine's record of it); it never waits on a box: it answers from each running box's last answer (kept up with its stream; a box gone to sleep let go of) and asks again behind it, each box on its own (one that hangs holds back no other), the next read showing what that found and a session it found new or moved on a box not followed said as `session.state` cause `listed` (a followed box's stream says its own); the first list waits 500 ms at most, else says `your boxes are being asked` (`BoxFront.sessions` in `serve/src/box/boxes.ts`); and `watch` carries each followed box's events tagged `box` (its `command.ran` excepted; its `watch.gap`, in the box's numbers, says that box's events were lost, so read again), numbered by the local machine. A box is followed while it holds an open session: one the local machine launched, or one its own `session list` named (a watch connecting looks); an idle box is not followed and still sleeps. A dropped link is reconnected after `followRetryMs` with `--since <the box's last seq>`, only to a box EC2 says runs.
