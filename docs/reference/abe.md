# Abe

Abe's packages, its CLI contract, the command table and how to add a command, an event or a port; then how its tests are written.

The `abe` command and `abe serve`, the one long-running process every client talks to (VimStorm, agents, scripts). Decisions: ADRs 0013, 0015.

```sh
cd abe && bun install
bun test                  # every package's tests
bun run typecheck         # strict tsc: the workspace, plus core and ui with no Bun/Node types
bun run lint              # eslint (type-aware) + prettier --check; lint:fix rewrites
bun run build             # dist/abe-darwin-arm64, dist/abe-linux-arm64 (bun build --compile)
bun packages/serve/src/main.ts status --json   # the CLI from source
```

The compiled `abe` never reads the `.env` or `bunfig.toml` of the folder it is typed in (`scripts/build.sh`), and the `serve` a client starts gets the client's environment on an allowlist (`serveEnv`): no cloud keys, nor a checkout's env file a shell loaded.

On a Mac `../install.sh` builds `dist/abe-darwin-arm64` into the app (`VimStorm.app/Contents/MacOS/abe`, `app/scripts/bundle.sh`) and links `~/.local/bin/abe` to it.

## Packages

| package   | holds                                                                                                                                                                                                                                                                                                                | may import                                                                                                  |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `core`    | pure rules, the command table, the CLI contract (`contract.ts`), the port interfaces (`ports.ts`)                                                                                                                                                                                                                    | `zod` only; no IO, clock, env, timers (tsconfig has no Bun/Node types; eslint bans `Date.now`, `process` …) |
| `ports`   | one adapter per outside system (socket, processes, locations, clock, GitHub through `gh`, Azure DevOps Boards over REST with an `az` token, AWS through `aws`, Docker, the box's git mirrors, the org store, Sheets on disk and their local origins)                                                                 | `core`                                                                                                      |
| `serve`   | the process: socket server, CLI client, handlers wiring `core` to `ports`; `src/main.ts` is the binary (`abe hook` first, then `app.ts`)                                                                                                                                                                             | `core`, `ports`, `hooks`, `ui`                                                                              |
| `ui`      | screens as trees of design-system components (`components.ts`), the bridge's frames (`protocol.ts`), the pure screen runtime (`runtime.ts`); see The shell bridge                                                                                                                                                    | `import type` from `core`, `zod`                                                                            |
| `hooks`   | `abe hook` (Claude Code hooks → the session's socket) and its own minimal socket client: gives up 1 s after start (AskUserQuestion's PreToolUse 4 s and a PermissionRequest 615 s, for its held card: both print serve's answer; UserPromptSubmit 615 s, for the turn's start snapshot), else prints nothing, exit 0 | `import type` from `core` (values only from `@abe/core/permission`, for PermissionRequest), Node built-ins  |
| `testing` | the harness, fakes, the dependency-graph check                                                                                                                                                                                                                                                                       | everything; only test files import it                                                                       |

`packages/testing/src/graph.test.ts` reads every import and fails on any other edge. Test files are exempt from this table, but not from the folder rules.

Inside a package, a folder under `src` is a module (ADR 0024). Each package lists its folders in `packages/<package>/folders.ts`: the folders each may import, its interface file (`index.ts` unless named) and the private files its own tests may import as seams. A file imports another folder only through that folder's interface, and only a folder its row names; another package's import of core, ports or ui goes through a folder's interface too. A test imports its own folder's interface and seams, the interfaces its folder may import, the harness and other packages' entry points. A cycle between folders fails. `unswept.imports` lists the folders not yet laid out this way; the graph skips their imports. That list only shrinks, and a folder on it that breaks nothing fails until it comes off.

## The CLI contract

- `abe <noun> [verb] [positional…] [--flag value…] [--json]`. Global flags: `--json`, `--no-start`, `--help`, `--on <box>` (the command goes to that box's `serve`, see Your boxes).
- `--json`: stdout is exactly one line, `{"ok":true,"data":…}` or `{"ok":false,"error":{"code":"<kebab-case>","message":"…"}}`. A usage failure also prints the usage on stderr.
- Exit codes: 0 ok, 1 refused or failed, 2 usage, 3 `serve` unreachable.
- Socket: `$ABE_SOCKET`, else `serve.sock` in the state directory (`$ABE_STATE_DIR`, else `$XDG_STATE_HOME/abe`, else `~/.local/state/abe`); a detached `serve` logs to `serve.log` there. One serve per socket: it takes `serve.lock` beside it (the OS's lock, gone with the process) before it touches the socket, binds the socket aside and moves it in place, removes it at stop only while it is still its own, and checks every 5 s that it is (bound again when gone); a start finding the lock held by a serve that answers nowhere for 10 s ends it (SIGTERM, then SIGKILL) and takes over. One JSON line each way per connection: `{"v":1,"argv":[…],"cwd":"…"}` → `{"v":1,"exit":n,"stdout":"…","stderr":"…"}`; a refused request (bad JSON, any other `v`) also carries `"error":{"code","message"}` (`unsupported-version`, `bad-request`).
- `abe watch [--since <seq>] [--json]` keeps its connection: `serve` sends one frame per event, `{"v":1,"event":{"seq","at","type","data"}}`, and the client prints the event as one JSON line (`--json`) or one readable line. `seq` rises by one per event within a `serve` (`serve.started` is 1); `--since` first replays the held events after it from a ring of the last 10,000, with one `watch.gap` first when some are gone. Ctrl-C exits 0; `serve` ending the stream exits 3. A refused watch gets an ordinary reply frame. `command.ran` names every command a `serve` answered: `help` and usage failures the client answers itself never reach it.
- The client answers `help` itself, runs `abe serve` in the foreground, and sends everything else to `serve`, starting one detached when the socket does not answer and waiting up to 5 s (never inside a workspace, `ABE_WORKSPACE`, or on a box, `ABE_BOX`: there `serve` is the box's unit).

## Adding a command

A new command touches one core folder and one serve folder: its domain's (`card list` the board's, `workflow list` skills').

1. A row in the domain folder's `commands.ts` (`packages/core/src/<folder>/commands.ts`, rows such as `BOARD_COMMANDS`, gathered into `COMMANDS` by `core/src/contract/commands.ts`): `noun`, `verb`, `summary`, `inSession`, `args` (an `ArgsSpec`: positionals in order, then flags; a flag key `dryRun` is typed `--dry-run`; a repeating flag is given again for more), `result` (a zod schema in the noun's folder) and its human text: `text`, or `says` naming the result's one string field that is the whole text, or neither for none. Help, usage and validation follow from the row. A new folder's rows get one spread in `COMMANDS`.
2. Its handler in the same domain's serve folder (`packages/serve/src/<folder>/`), in a handler set its `index.ts` spreads into the folder's handlers (`BOARD_HANDLERS`, typed `HandlersFor<typeof BOARD_COMMANDS, Ctx>`): the compiler insists on one per row. Its `ctx` is the request's facts (`cwd`, `settings` at its checkout, `session`, `hub`, `inside`), the ports routed at its checkout (`ctx.ports`, `serve/src/routing`: Tracking, Board, Git, Pipelines, Review and AWS, Local mode's held writes among them) and serve's own modules (`ctx.serve`). A file the caller names on argv (`--body-file`) is read by the handler, relative to the request's `cwd`. It gets typed args and returns an `Outcome`: `{ ok: true, data }` or `refused(code, message)`. `dispatch` checks `data` against `result`.
3. A `--json` test through the CLI seam, success and refusal.

## Adding an event

1. A row in `EVENTS` (`packages/core/src/contract/events.ts`): its type `<noun>.<event>`, its `data` (a zod schema) and its `text` (the readable line's words). `Event` and `EventType` follow from the table, so `emit` refuses any other type or data, by the compiler and at run time.
2. Emit it from `serve` with the journal: `events.emit('<noun>.<event>', data)`.
3. A test through `abe watch --json`.

## Adding a port

1. The interface in `packages/core/src/ports/ports.ts`, named by what core needs (`Clock`), plain data in and out.
2. The adapter in `packages/ports/src/<system>.ts`; IO only, no rules.
3. A fake in `packages/testing/src`: a small hand-written one (`fakeClock`), or `held(name)` for calls the test answers one by one (`resolve` / `fail` the oldest equal call, `settled()` fails a test that left one open). A real outside process gets a fake process (a fake `gh` script) rather than an in-memory stand-in.
4. Hand it to `serve` through its options (`ServeOptions`), never a module-level import, so tests swap it.

## Tests

Tests sit beside the code (`foo.ts`, `foo.test.ts`) and check what a client sees, never a module's insides.

**The fix rule** (26 Oct audit: the suite grew a test per fix). A fix adds a row to the existing table test at the module's interface, in that module's test file. No new test file, no test named after the issue, no copy in another layer: the rule's table lives in `core`, `serve` tests the wiring once per command, `ui` tests rendering only. A new `cli()` test only for a new command's contract (exit code, `--json` shape); behaviour goes through in-process `scenario()` / `served()`. A file that must stay on `cli()` starts one per `describe` (`beforeAll`), not one per test. If no table fits, the interface is the wrong shape: deepen it first. Reviewers (code-review's Standards axis) flag: issue-numbered test names, new test files, cross-layer copies, a new `cli()` per test.

**Keep, fold or delete.** Every test file in a folder you sweep gets one of three answers.

- Keep a test that goes through its module's interface and checks a rule no other test checks. If its name cites an issue, rename it to the rule.
- Fold a test that checks a real rule from the wrong place: a test file per source file, single tests of one rule, a scenario copied with one field changed, a test that reaches past the interface. It becomes a row in the table at the module's interface, and its file goes.
- Delete a test that repeats a row another layer owns, asserts private state or a private helper, checks a constant or a one-line renderer, or repeats a scenario another test covers. First name the test that covers the same behaviour. If there is none, fold it instead. A test that guards behaviour nothing else covers is never deleted.

Each rule has one owning layer: core owns rules, serve tests wiring once per command, ui tests rendering and keys, the window's Rust tests drawing. Ui imports core's words through core's interfaces instead of keeping a copy and a parity test. `bun run count` prints test files, tests and cases per suite (a table row is one case); `bun run prose <path>` lists what the prose check finds there, swept or not (ADR 0024).

- **In-process first**: `served({ env })` is a `Cli`'s `run` / `json` / `runWith({ cwd })` / `jsonWith` over `scenario()`, with no `abe` process per run; `stdin`, more environment per run, `spawn` (`abe watch`) and client-only commands (`ui bridge`, `serve stop`, `login`) need `cli()`. `s.scenario.clock` is its fake clock: a date in a test is read from it, not `new Date()`. `macServed(env)` is the local serve as `app.ts` builds it from `env` (boxes over `$ABE_BOX_LINK`, board, AWS, GitHub) on this machine's time; `s.watch('--json')` streams `abe watch`.
- **CLI seam** (one contract test per command): `cli()` from `@abe/testing` runs the real `abe` as a process on a temporary state directory and socket, with `PATH=/usr/bin:/bin` (kept: `ABE_LOGIN_PATH=off`) and its own `HOME`; `abe.json(Schema, 'status')` returns the exit code and the document read with `Schema`; `close()` stops the `serve` it started, and a serve whose test process is gone (failed, timed out, killed before `close()`) stops by itself with its sessions' tmux (`ABE_SERVE_OWNER_PID`). `cli({ binary })` runs a compiled binary the same way.
- **Fake `aws`** (`fakeAws()`, the same `fakeTool` as `gh`): STS's and Secrets Manager's answers (`stsAssumed`, `secretText`); `assumedRoles(aws.calls())` reads each AssumeRole's role, SourceIdentity and duration.
- **Fake S3 `aws`** (`fakeS3()`, `testing/src/tools/fake-s3/aws.ts` under Bun): `s3api put-object`, `get-object` and `list-objects-v2` over a folder, printed and failed as the CLI does (`NoSuchKey`); `deny([prefix])` makes puts there AccessDenied, as the bucket policy does.
- **Fake `gh`** (`fakeGh()` from `@abe/testing`): a script first on `PATH` (`cli({ env: { PATH: gh.path } })`) answering GitHub's shapes (`ghIssue`, `ghPrView` …) by the first pattern its argv contains, else a 404; `gh.calls()` gives each call's argv, environment and stdin.
- **Fake Azure DevOps** (`fakeAdo()` from `@abe/testing`): `fake-ado/server.ts` run under Bun as its own process on a free port, seeded from a JSON file (default `ADO_SEED`), its writes seen by the next read; `--expired <token>` answers that token 401. `abe` reaches it through `ABE_ADO_BASE_URL` (`ado.env`) with `ado.board` as the `board` setting; `fakeAz({ tokens })` hands out the tokens. A scenario that reads and writes cards without the server takes `fakeBoard([card(…)])`. On a box, `scripts/demo-board.sh <box> <seed.json>` (the demo, no real Azure DevOps org) builds the server for Linux, puts it and the seed in the artifacts bucket and, through `abe box attach`, runs it as the unit `abe-demo-board` on the box's `127.0.0.1:18991` with a fake `az`, the box's `serve` given `ABE_ADO_BASE_URL` (a drop-in; restarted only when it changed); run again it reseeds the board. The local machine reads the same board through `abe box forward <box> 18991`.
- **Fake `claude`** (`fakeClaude()`, `testing/src/tools/fake-claude/claude.ts`): an executable first on `PATH` that reads its `--settings`, runs their hook commands with Claude Code's payloads (each waited for), writes a transcript under `$HOME/.claude/projects`, echoes typed lines as new turns (`/exit` ends with `SessionEnd`) and writes what a test reads into `<worktree>/.fake-claude/` (`claudeOutput`: its env, argv, hooks, `abe` runs, typed lines). `scriptClaude(home, steps)` scripts its first turn (hooks, `abe` commands, its answer). It runs in a real `tmux` (`tmuxPath()`, `ABE_TMUX`); `cli().close()` kills the `tmux` server its `serve` started.
- **Org store**: a temporary folder as `ABE_ORG_STORE=file://…` (`fileOrgStore(dir)` for `scenario({ org })`); two `cli()`s on one store are two people.
- **In-process serve**: `await using s = await scenario()` starts a real `serve` in the test with fake ports (`s.clock` is a `fakeClock` at `T0`); `s.request('status', '--json')` speaks the socket protocol.
- **The org preset**: `await using o = await orgScenario({ cards })` is that serve with the setup most serve tests need. It has an org with team `web` on a board, your Layer in that team, a `demo` repo with one commit (`origin` gives it a GitHub remote a bare repo answers), the fake board and the fake `claude` on the sessions' `PATH`. Build on it instead of copying that setup.
- **Screens**: `driveScreen(screen, { params, size, now, replies })` drives one screen as the bridge does. Its menus, confirms and dialogs go to Command mode over it, keys go to the top layer, and Command mode's rows come back to the screen. A test reads `tree`, `layer`, `commands`, `effects` and `here`, never the state, and answers reads by their argv (`answer(repliesBy({ 'card list': … }))`), so a screen's read ids can change. `driveLayer(layer)` drives Command mode or another layer alone. `driveBoard({ world })` is the Board on it, its reads answered from a sprint of cards, runs and sessions (`boardReplies`); a Board mode's tests go through it too.
- **Rule tables** in `core`: plain `test.each` over a pure function (`parse.test.ts`, `dispatch.test.ts`).
- Run your own files while working: `bun test packages/<pkg>/src/<file>.test.ts`.
