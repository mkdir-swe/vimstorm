# Sessions in your environment

How a session runs on your box once `serve.target` is `cloud`, and how one moves between this Mac and a box.

## In your environment

`serve.target` (`cloud` or `local`) defaults to `cloud`: your environment is your boxes. A value it does not take is refused by `settings set` and, written in a Layer file, read as `local` and listed by `settings problems` / `check`: a typo never means cloud. With `serve.target: cloud`, `abe session launch --card <id> --repo <checkout | owner/repo>` locally goes to the card's box: one Workspace, one box (ADR 0016 as amended, ADR 0021), an EC2 instance of yours from the launch template `abe-box` named `<repo>-<card>` (`boxName`), tagged `abe:owner` (your GitHub login), `abe:box`, `abe:repo`, `abe:card` and `abe:title` (its volume `abe:owner`, `abe:box`), running as your box role `/abe/box/abe-box-<login>-boxes` (`boxRoleName`). Rules in `core/src/box/cloud.ts` and `core/src/box/box-session.ts`, the local machine's flow in `serve/src/box/cloud.ts`, the box's in `serve/src/box/box-sessions.ts`.

- **Placement** (ADR 0022, `placeRepo` in `core/src/box/box-place.ts`): one box per repo, a box workspace per card on it. The repo's box (its `abe:repo` tag; an **old box**, a 2.2 box made for one card with its `abe:card` tag, is never placed on, though it counts while it runs) running or starting is used; asleep (or stopping), it is woken; none, it is made, named for the repo (`demo-shop`; 4 hex of the repo after it when another of your boxes has that name, `boxName`), at `box.size` (default m8g.xlarge, never past `limits.maxBoxSize`), its tags `abe:owner`, `abe:box`, `abe:repo` only; a box made a moment ago and not listed by EC2 yet is used by the next launch on its repo, never made twice; but when your running and starting boxes plus the requests already Queued reach `limits.maxBoxesPerPerson`, a wake or a make is Queued (a stopped box never counts; a woken one counts once it starts). A wake by name (`abe box start`, the Boxes tab's Wake, `--on` or `box keep` on a sleeping box) counts the same and, as `box up`, is refused `box-limit` at the limit, never Queued (`abe box place <card> --apply` queues it); so does `box resize` of a sleeping box, which starts it. `abe box attach`'s own wake (the client's, no queue there) is not counted yet. The queue is one, in order, kept by the local machine's `serve` across restarts (`<state>/cloud/<id>.json`, `place-<card>-<hex>.json`, gone once answered): Queued launches and `abe box place --apply`s; its oldest is placed once it fits (a box stopped or deleted, or the limit, read anew in the checkout it was asked in, risen; a `settings.changed` of the key looks at once, else every 15 s), then the next. `abe box place <card> [--repo <r>] [--title <t>] [--apply] --json` answers `{"box","action":"use"|"wake"|"create"|"queue","boxes","limit"}` (`boxes`: your running and starting ones); `--apply` wakes or makes the box (`box.state` `starting`, then `running` once its `serve` answers), or holds it Queued (`box.state` `queued`, cause `place`). Tests: the rule table `core/src/box/box-place.test.ts`, the CLI seam with the fake EC2 `serve/src/box/box-place.test.ts`.
- **The chain**: `Boxes.up` (made from the launch template, or started) → EC2 says it runs → `abe workspace up` on the box (idempotent; the box's startup runs it too) → `abe session run --id … --repo … --card … --text <the card's words as JSON> --layer <your Layer as JSON>` there. The local machine reaches the box's `serve` through the `BoxLink`: `ssh` through the EC2 Instance Connect Endpoint by default (below), `ABE_BOX_LINK=ssm` SSM Run Command (`ssmLink`: `run` only, no stream, no terminal), `exec:<path>` an ssh-like command (`<path> [-t] <box> -- abe …`), `docker:<container>` for the stand-in box on a local machine's Docker, `socket:<path>` in tests. States go `queued` → `starting` → the box's hook-driven `working` / `waiting` → `ended`.
- **Launch steps** (`core/src/box/launch.ts` the steps, `ui/src/board/launch.ts` what is said of them): while a launch is `starting` its session carries `launch` (`LaunchProgress`: step, since, the launch's own start, box, `new` / `wake` / `use`, the box's detail, the steps done with their times), said as `session.step` on every move: `box-starting` (EC2 asked; `box.state` `starting`, cause `launch`), `box-booting` (EC2 runs it; the box followed from here), `workspace` once its `serve` answers `status` (`box.state` `running`), the box's own `workspace.step` events from `abe workspace up` (`mirror`, `base-image` / `image` with Docker's `step n/m` from the build's output lines, `database`, `clone`, `container`) as `base-image`, `repo-image` and `workspace`, then `claude-starting`; gone once it runs. A launch never goes back a phase (box, workspace, claude) and the local machine's own step never replaces one the box said. The Board's rail, Chat's header and Sessions say the step's word (`Box booting`, `Building image`) with the launch's clock by the second (screens with one ask the bridge for a tick a second, `Screen.seconds`); Chat's body lists the steps done with their times and the one now; past a step's budget (`launchLook`: QA F's measures, an older abe on a new box with its images in the workspace step) it turns amber with what is late and the box's log / Restart serve commands, red from 12 min, and the launch given up at 15 min ends with a reason naming the step it hung at.
- **In the container**: the workspace runner (`ports/src/docker/workspace-runner.ts`) runs everything through `docker exec`: the managed settings as root (`/etc/claude-code/managed-settings.json`, `managedSettings`: `allowManagedHooksOnly` and `allowManagedPermissionRulesOnly`, so no other settings file (a `.claude/settings.json` the agent writes, the session's `--settings`) adds a hook or a rule, the allow rules (the in-session `abe` commands, the repo's sources' `sourceRules`) given here and the clone's and Before's `.claude/settings*.json` denied to edits and to commands (by their paths: the sandbox takes no glob on Linux); the hooks run `abe` by its path, `/usr/local/bin/abe`; `abe hook <event>` for every event; the sandbox on, its sandboxed commands run without asking (`autoAllowBashIfSandboxed`), `failIfUnavailable`, no unsandboxed retry, nested in the unprivileged container; credential files, `/proc/*/environ` and the sessions' variables files (`~/.abe/sessions/*/env` to the file tools, the folder `~/.abe/sessions` to commands) denied, the network GitHub, npm, and AWS's STS and the Reach environments' regions only, `CLAUDE_CODE_OAUTH_TOKEN` unset for commands; the workspace socket, every session's socket folder and the container's tmux server denied, the session's own folder opened again by its `--settings`; `model` the coordinator's from `core/src/layer/role.ts` lowered by `allowedModels`, `availableModels` those), `gh auth login --with-token` (token on stdin) and `gh auth setup-git`, the AWS profiles as `~/.aws/config`, the clone's folder trusted in `~/.claude.json`, then `claude --settings … --mcp-config [the box's ~/.claude.json, for the repo's sources] /run/abe/mcp.json --strict-mcp-config` in tmux through `env -i` from a variables file the pane removes. Each session's socket is `<state>/workspace/s/<id>/session.sock` (`/run/abe/s/<id>/session.sock` inside); a request there is that session's: its `hook`, its own `session list|show`, `reach env|profiles|creds` (its AWS profiles' `credential_process`), `sheet save|list|find|show`, `status`, `browser` and its Factory run's own `factory` rows (`INSIDE_SESSION`; other in-session rows act on the box itself); the workspace socket itself answers only `help`, `status` and `browser`.
- **Environment** (`boxSessionEnv`): `HOME`, `USER`, `PATH`, `TERM`, `LANG`, its `ABE_SOCKET`, the image's fixed switches, the container's `DATABASE_URL` and `ABE_WORKSPACE`, the cloud Reach names (the four fixed shapes only, `parseReachName`; writes only where granted), `CLAUDE_CODE_OAUTH_TOKEN`; nothing else.
- **Logins** (`Logins`, `secretLogins`): `abe/<owner>/claude-token` and `abe/<owner>/github-token` read as the box (`ABE_OWNER`) from Secrets Manager, straight into the container; never printed or kept.
- **Idle stop** (ADR 0021; `core/src/box/box-idle.ts`, `serve/src/box/idle.ts`, `ports/src/aws/box-host.ts`): a box's `serve` (`ABE_BOX`, `ABE_BOX_NAME`) looks every minute (`$ABE_IDLE_EVERY_MS`) and, once it has heard no Claude Code hook and nothing kept it up for `box.idleMinutes` (yours on this machine, handed to the box by a cloud launch (ADR 0030), default 30, at most 1440; lengthened only by an Override, read in the box's home on every look), says `box.state` `stopping` (cause `idle`) and runs `sudo -n /usr/sbin/shutdown -h now` (the box's `serve` runs as `ubuntu`, which has passwordless sudo for everything, cloud-init's default, and the docker group; the box module's sudoers rule names this shutdown and `abe-grow-root` too; its instance-initiated shutdown is `stop`, so the disk is kept). Kept up (`IDLE_KEEPS`): attached (a login with a terminal on the box, `who`: `abe box attach`'s SSH, or a tmux client in the workspace), a session starting or working (one waiting on you with nobody attached does not), a Factory run waiting on its pull request; a look that cannot read them stops nothing; the idle time counts from the last moment one held. A failed shutdown is said (`box.state` `running`, cause `shutdown-failed`) and tried again after another idle time. `abe status` on a box gives `idle` (`minutes`, `activeAt`, `stopsAt`, `keptBy`), `waitingSince`, `waitingMinutes`, `soon`) and the local machine's `abe box list` shows it per running box in local time (`sleeps at 13:09 if still idle (30 min) · in 12 min`). **A session waiting on you** still keeps nothing up, but its box sleeps no sooner than `box.waitingMinutes` (yours on this machine as `box.idleMinutes`, default 120, at most 1440) after the oldest began to wait (`waitingSinceOf`, `sleeps at … if you have not answered`). `IDLE_WARN_MS` (5 min) before its stop the box says `box.idle` with `soon`: the Factory view balloons it once and the status bar's boxes widget reads `☁ demo-1 sleeps 13:09`, its click `abe box keep <box>` (kept awake until `box sleep`, as Keep awake everywhere). When the box goes down its open sessions end; one that waited on you says why and how to go on (`boxStoppedReason`, cause `box-slept`: `its box went to sleep while it waited on you (<box>, idle) · abe session launch --card <n> --repo <r> wakes it and starts a new session there: its branch and files are kept, the conversation starts anew`) when the box stopped on its own: its `stopping` (cause `idle`), or EC2 saying it is down and this serve did not stop it (`BoxFront.stoppedHere`); stopped by `box stop`, terminated or gone, it says `its box <box> stopped` (cause `box-stopped`). Sessions shows it as a `◆ Box slept` row whose ⏎ relaunches the card. The words: `session show` / `list` times local (`waiting on you since 12:35`; `--on <box>` text is the box's, UTC, marked ` UTC`), a Queued launch says why (`queuedFor`: the boxes counted and the limit), `box place` without `--apply` says what it would do (`applied`), `box list` gives each box your session's state (`BoxData.session`) over its workspace's, and Cost always reads `$0.84 today`.
- **Factory runs**: `abe factory run <card>` launches the same way with `abe session run --factory`, and the run lives in the box's `serve`: where its hooks arrive, its checks run, the pr stage pushes and the deploy poll runs. The run's settings are read in the box's own checkout of the repo (`Mirrors.checkout`: `<state>/mirrors/checkouts/<owner>/<repo>`, a worktree of the mirror at its default branch), never the workspace's clone; everything in the run's worktree (the agent's reports, `.scratch/<card>/…`, the checks' commands and diff) goes through the `RunTree` port (`ports/src/mac/run-tree.ts`): `localRunTree` on a local machine, `containerRunTree` (`docker exec` as the workspace's user) on a box, where a report is read only as a file inside the worktree; the session's logs (its transcript under the container's home, the card's checks, reports and Evidence) are read there too. A Factory session starts in `acceptEdits` (`FACTORY_PERMISSION_MODE`, its own `--settings`, a local one's too): edits and sandboxed command lines, compound ones included, never wait on a prompt; the sandbox and the deny rules hold. Nobody is at a box Factory session's prompts, so its hook answers the ones Claude Code still asks (`unattendedAnswer` in `core/src/session/permission.ts`; only a session launched with `--factory` in a workspace is `unattended`, a person's session there and any local one keep Claude Code's dialog): Bash allowed while it stays sandboxed (`dangerouslyDisableSandbox` refused), Read / Glob / Grep only under `/workspace` by the path as written (`..` resolved) and by its real path (links resolved by the hook inside the container, `abe_real_paths` in the payload; a Glob with `..`, `~` or a `/` inside braces refused), `mcp__chrome-devtools__*` allowed, anything else refused with why and `abe factory needs-you`; each answer is a `permission` field (tool, allow / deny, reason, a short redacted input summary) on its line in `hooks.jsonl`, shipped with the session's logs. A box's checks run there with the workspace's own environment (its `DATABASE_URL`, its tools), under coreutils' `timeout`; the repo pack's `setup` runs in the clone before `claude` (a mark `/workspace/repo.setup` once it passed; a failure puts the run at Needs you); the Verification pack's scripts go through `abe run <script> [args…]` (dev alone: `--env test` or `prod` refused `env-not-here`; a hook point's script by its role or path, `.claude/skills/run-app/scripts/<name>` or the bare `<name>` in the clone, or by its absolute path in Before's worktree; `packScript` in `core/src/box/box-session.ts` over `runScriptIn`, `core/src/repo-hooks/`, with the hook points the Mac handed from its committed `abe.yaml`), which the box's `serve` runs in the container outside Claude Code's sandbox (a sandboxed call's `localhost` is its own on Linux, and the app must outlive it for the browser), so no command leaves the sandbox as the session's user (no `excludedCommands`); checks, `setup` and `abe run` run as the workspace's script user `abe-run` (uid 1001, `CONTAINER.runUser`), which shares the clone and `.scratch` with `abe` through the group `abe-work` (setgid folders, umask 002; the clone script gives an older volume to the group once) but cannot read `abe`'s home (700: Claude Code's and gh's logins), its processes' environment, or a session's socket folder (the session user's own, mode 700, `sessionDirAccess`), and cannot write what `abe`'s own unsandboxed code reads: git's files (`core.sharedRepository 0644`, `.git` not group-writable), Claude Code's project settings (`.claude`: readable, so a check walking the tree reads it, never writable, `settings.local.json` and a `.credentials.json` 0600 before anything is widened, a link in its place removed and nothing followed; `claudeFolderShell`; a file Claude Code writes there later has the session's umask until the next `up`) and, with `/workspace` and the clone sticky, none of `abe`'s entries there are renamed or replaced (the clone, Before's worktree, `.git`, `.claude`, the setup mark); the managed settings are written only into a root-owned `/etc/claude-code` (a repo layer's folder of `abe`'s is refused); Before's worktree is `/workspace/repo-base` beside the clone (the managed settings' `sandbox.filesystem.allowWrite`); serve's own git there runs with no hooks or fsmonitor, and a report it writes stays inside the worktree; the pr stage's push and its GitHub reads go through git and `gh` in the container (`workspaceGit`, `workspaceGh`), on the login the session's `gh` has there. A box stays awake while a run waits on its open pull request (the deploy poll, `waitsOnPr`), not only while a session runs, and the local machine follows its events as long (asking the box once its session ends whether the pull request opened), so merge, deploy and Done reach the local machine's `abe watch`. At Done its session, idle at its prompt since the pull request, is stopped (`doneByItsPr`): nothing reads it as waiting on you, and the box sleeps `box.idleMinutes` after, as any idle box. `workspace up` sets the clone's git identity to the person's (`gh api user` with their GitHub login, in the container: their name, `<id>+<login>@users.noreply.github.com`; `author` in its answer), so Claude Code's commits are theirs. The local `factory status` adds each running box's runs (asked through `forward` in `serve/src/box/cloud.ts`, the one call that replaces it; a sleeping box's as last heard), `factory checks` goes to the card's box (only while it runs: `box-asleep`), and the box's `factory.stage` events are said again on the local machine's `abe watch`. A Needs you is answered as any session is: `abe session send` or `attach`.
- **Resize** (`resizeRefusal` in `core/src/box/cloud.ts`, `serve/src/box/box-resize.ts`): `abe box resize <box> <size> [--yes]` changes the box's EC2 instance type (`BOX_SIZES`, `m8g.large` up to `m8g.16xlarge`): `Boxes.stop`, then `Boxes.resize` (`modify-instance-attribute`) once it is stopped, then `Boxes.start` (never a new box: one gone meanwhile is `no-box`); a sleeping box is just started at the new size. Refused: a size Abe does not know (`size-unknown`), one over the `limits.maxBoxSize` in force (`size-over-team-max`, even with `--yes`; yours only lowers that key with a plain entry, raising it takes an Override with its reason), sessions running on a running box (`sessions-running`: the box's own `abe session list` and this `serve`'s launches there; `box-unreachable` when the box cannot say) unless `--yes`, whose stop ends them (`box-resized`), a box mid-build (`box-busy`). It runs one at a time with placement, so no launch uses or wakes the box between its stop and its start. the org Terraform's `terraform/modules/teams` gives the developer policy its sizes (IAM refuses any other instance type), never past the largest team maximum. Tests: the rule table in `core/src/box/cloud.test.ts`, the CLI seam with the fake EC2 (`fakeEc2()`) in `serve/src/box/box-resize.test.ts`.
- **The resize ask at a launch** (ADR 0022, `launchShortAsk` in `core/src/box/box-load.ts`): a cloud launch placed on its repo's running box (`use`) reads the box's load first (`workspace status`, within `SHORT_READ_MS`; a load not read never holds it up; a woken or made box is not asked). Under 3 GB memory or 10 GB disk free it is refused `box-short`, the error's `boxShort` the question: its line, then Resize to the next size within `limits.maxBoxSize` (recommended, short of memory only: a larger box has the same disk; says the box stops ~2 min and which working sessions end mid-turn), Launch anyway, Cancel. Never Queued, never a second box. A Reopen onto its running box (`session reopen`) and a Move to cloud (`session move-to-cloud`: its local claude stopped by then, the answer moves the ended session) ask the same, both with `--short`. `--short resize` (on `session launch`, `factory run`, `session reopen` and `session move-to-cloud`) resizes as `box resize --yes` does, then launches; `--short anyway` launches. The Factory screen asks it as a menu headed by the line (`ui/src/board/launch-short.ts`, resting on Launch anyway) and sends the launch again with the answer; Retry run and Reopen from the Board, Sessions or Chat (`withShortAsk`: their argv kept by run id) and Move to cloud (Command mode, which ran it) show the same menu, each answer run again with `--short` (`shortRerun`). Tests: the table in `core/src/box/box-load.test.ts`, the serve seam in `serve/src/box/cloud.test.ts`, the screen in `ui/src/board/card-actions.test.ts`.
- **A box's cost, its workspaces' shares, busy** (ADR 0022): `costToday` adds the root disk (`BOX_DISK_GB_MONTH_USD`, gp3 in eu-west-1; the disk its load last said, else the launch template's `BOX_ROOT_GB`) since midnight, asleep too (`diskHourly`: a stopped box's Cost grows at the disk's price alone). Each workspace row's Cost is its rough share, dim `≈$0.14`: the box's cost split by its busy minutes today (`workspaceShares`; busy = this machine saw its session starting or working at a `box list`, kept in the uptime log as `<box> #<card>`). A box whose last load read has memory used or CPU at 85 % or more (`boxBusy`) is listed `busy` with the next size within `limits.maxBoxSize`; the Factory screen balloons `demo-shop is busy · Resize to m8g.2xlarge…` once a day a box (`boxBusyKey`). Linked's Box row reads `☁ demo-shop #101 · running` (an old box its name alone) and opens the Boxes tab on that card's workspace row (`open` param `card`).
- **A run's end is pinned at its start** (`Run.pinned`): auto merge and `factory.done` are read once from the run's checkout as it starts, so a later launch on the same box (another card, another Layer handed to the box) never changes them for a run already going; a run from before reads them live.
- **Local mode** has no boxes: a launch with `--target cloud`, Move to cloud, `abe box place` and `abe box up` from a local-mode checkout are refused `local-mode`.
- `send`, `attach`, `stop` and `show` go to the box; `list` is the local machine's, a session whose box sleeps is ended. `abe session attach <id>` locally runs `abe box attach <box> --session <id>` (below), which runs the box's own `abe session attach <id>` over SSH: `docker exec -it abe-workspace tmux attach-session -t =abe-<id>` there.
- **No AWS login** (none, or expired): `session list` still shows this machine's sessions and says why your boxes were not read (its `boxes` field; one stderr line without `--json`), naming `aws sso login --profile <profile>` and that `serve.target: local` in a Layer keeps you on this machine; a `watch` gets it once as a `boxes.unread` event. A failed read is kept for the scan's minute (EC2 is not asked again meanwhile), and the scan's read waits 5 s at most. A launch into your environment is refused `aws-auth`, naming the `aws sso login`.
- Tests: rule tables (`core/src/box/cloud.test.ts`, `box-session.test.ts`); the chain through the CLI seam (`serve/src/box/cloud.test.ts`): the real `abe` locally, the fake EC2 (`fakeEc2()`, `testing/src/tools/ec2.ts`: a fake `aws` with IAM's ABAC in front, `fake-ec2/aws.ts`) and its fake box shell as the link, a box `serve` in the test with the fake Docker port whose workspace container is `standInWorkspace()` (the fake `claude` in a real tmux, reading the stand-in's managed settings).

## Download locally and Move to cloud

recovery only: no flow and no confirm. Rules in `core/src/session/move.ts`, handlers in `serve/src/session/move.ts`, the copy in `ports/src/git/move.ts` (`Mover`).

- `abe session download <id> [--repo <checkout>]` (the checkout defaults to the cwd and must be the session's repo, else `wrong-repo`): the Workspace's box is reached only through `abe box attach <box> -- …` (which wakes it; `$ABE_BOX_ATTACH` names a fake in tests). One that does not answer is `box-unreachable` with the way out (`abe box up <repo> <card>`). Its `claude` there is stopped first (`session stop` on the box's serve), then one tar crosses on stdio: a git bundle of the branch to its head (the whole history), the staged and the unstaged diff (`git diff --binary`), the untracked files and `.scratch/` that `movePlan` lets go, and the transcript. On this machine it lands in a new worktree at Abe's place (`<repo>-wt/<id>-<slug>`; one there already is `worktree-taken`): the branch at the same head, the staged diff in the index, the unstaged one on top, the files, the transcript as a log in `.scratch/<card>/sessions/<id>.jsonl`. The same session (its id) goes on here as a local session with read names only (`sessionReach(…, 'local')`), the repo pack's setup run again: `claude --resume <its Claude session>` after the runner wrote the log as Claude Code's own session file (`~/.claude/projects/<folder>/<uuid>.jsonl`, each line's `cwd` the new folder: `resumedTranscript`), its state from its hooks as any session's. The cloud record is marked `moved` (ended, `cause: moved`, no longer listed or known), the box stopped through the same stop as `abe box stop` (its disk kept), `session.moved` emitted.
- `abe session move-to-cloud <id>`: the reverse. The local `claude` stopped, the worktree packed the same way (nothing read from the box), then a launch on the card's box under the same id through the cloud launch's placement (Queued past `limits.maxBoxesPerPerson`, the pack waiting in `<state>/moves/<id>.tar` until a box stops or is deleted, or the limit rises); once `workspace up` ran, the pack goes into the clone through `abe box attach <box> -- …` (changes already in the clone are stashed first, never lost), then `abe session run … --resume <uuid> --transcript <log> --from <old folder>` there, whose workspace runner writes Claude Code's session file in the container's home. The local worktree is left as it was; the local record is marked `moved`. A move that does not land is refused ending `· <worktree> stays as it was` (the box could not take the pack: one line, `the box could not take the pack: …`); the session is this machine's again and a box the move woke or made is stopped again, its disk kept. `abe box attach <box> -- <argv>` passes every word as given, an empty one too.
- **Held to** (the review of its first cut): a move refuses before anything is stopped or made, in this order: the id and the card's open session on the receiving side (`session-exists`, `card-has-session`, `sessions.admit` / `cloud.admit`), a second move of the same session while one runs (`move-busy`), the worktree (`worktree-taken`); a download's worktree made by this run is removed again when the copy or the launch after it fails. The other side's pack is data: of its files only the plan's land, by name (`UNPACK` unpacks `files.tar` into a staging folder and takes the listed names from there); a path the listing has that no worktree lists (absolute, a `..` step, a `.git` component: `unsafeMovePath`) refuses the whole move (`unsafe-path`); its head must be a commit the bundle brought; a branch of that name on the receiving side with commits the moved head has not is `branch-diverged` (never `checkout -B` over it). The patches are git's own whatever the person's config (`-c diff.noprefix=false -c diff.mnemonicPrefix=false -c color.ui=never diff --no-ext-diff --no-color --binary`); both `tar -c` run with `COPYFILE_DISABLE=1`, so macOS adds no `._*` AppleDouble entries the box's GNU tar would extract as files. The Claude session resumed is the transcript's (`claudeSessionOf`, after `/clear` it is not the one started), the transcript's old folder the worktree's real path (the listing's `pwd -P`); a box's `session run --resume` takes only a Claude session id and a `--transcript` under `.scratch/`.
- **What crosses** (`LEFT_BEHIND`, a table): left behind are `node_modules/`, `.pnpm-store/`, `.venv/`, `.yarn/cache/` (packages), `dist/`, `build/`, `out/`, `.next/`, `.turbo/`, `coverage/`, `target/`, `*.tsbuildinfo` (builds), `.env`, `.env.*`, `.aws/`, `.npmrc`, `.netrc`, `*.pem`, `*.key` (credentials), and the repo pack's `move.leave` globs (`.gitignore`-like, read in the checkout); nothing that runs (servers, terminals) and no Reach writes. Ignored files are never listed, so neither are they copied.
