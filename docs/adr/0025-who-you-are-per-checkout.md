# 0025 · Who you are is set per checkout, in your own Layer

Status: accepted, 27 Oct 2026. Adds to ADR 0010 and 0011 (the Layers) and to how your environment is read from the Layers.

One person can work in two worlds on one Mac: a personal demo org and a work org. The settings that say who you are were global in your own Layer: the org checkout (`org.dir`), your team (`team`), your az login folder (`board.azureConfigDir`), your boxes' AWS profile (`box.profile`), and the gh login, which was always gh's active one. So a work repo read the demo org's az folder, the personal gh login and the personal AWS profile.

Your own Layer may now hold `checkouts: { <checkout folder>: { <key>: value } }`. Only these keys go in a block: `org.dir`, `team`, `board.azureConfigDir`, `box.profile` and `github.account`. `github.account` is new. It is the gh login Abe reads and writes GitHub as, and the one its sessions' gh uses. Where the settings are merged for a folder in a listed checkout, that block's values are yours there, over your file's own values. The folder can be the checkout itself, a folder in it, a card worktree beside it (`<checkout>-wt/…`) or a linked worktree of it. Everywhere else your file's own values stand. `abe settings set <key> <value> --here` writes a value into the block for the checkout you are in, under the main checkout's real path. `null` takes it out, except for `team` and `org.dir`: there `null` is kept and means none: no team Layer, or no org checkout (and so no org or team Layer, even with `$ABE_ORG_DIR` set), in that checkout; `abe settings unset <key> --here` takes any entry out.

The block is part of your Layer, not a Layer of its own. The merge reads it in `readLayer`, when your Layer's source names the folders it is merged for. So `settings.at(dir)` gives every reader the value in force at the checkout, with no new step in the order. `explain` marks the step with its checkout, and Settings shows it on Local mode's page and on the row's source line. A shared Layer writing `checkouts` or `board.azureConfigDir` is refused (`personal-only`): both are yours alone.

`github.account` never switches gh's active login. Abe reads its token with `gh auth token --user <login>` and holds it in its own process only. Each of Abe's gh calls for that checkout runs with `GH_TOKEN` set: GitHub reads and writes typed there, the fresh look at its pull requests, the PR review, Pipelines, Improve's team proposals and retro reads, the Factory's pr stage and the install's Connection check. A session launched in that checkout gets the same `GH_TOKEN` through its environment file (mode 600), and it is redacted from its logs. When gh has no such login, the launch is refused and says so. The token is never printed, logged or written into a reply.

The board reads cards with the az login of the folder in force where it was read. `boardOf` carries the folder on the board ref, and the Azure board keeps one token reader per folder. Azure Pipelines read a checkout's runs (`--repo`'s, else where it was typed) in its folder too, one reader per gh login and folder. A `$AZURE_CONFIG_DIR` that serve's own environment sets still overrides the Layers, as it does for every key of your environment. Logins checks az in that folder and checks that the named gh login is signed in. `abe login az` on the Mac signs in to the az folder in force where it runs (kept, then stored for your boxes as before) and says which; with no login secret within reach it signs in there all the same and says your boxes get none. With no folder it keeps a private one.

Your boxes follow `box.profile` the same way. A launch or `box up` in a checkout whose profile is not serve's own makes its box on that profile's EC2, and Reach's AWS and its secrets are that profile's there, the log shipper's for each session's checkout too. `box attach` and `box forward` reach a box on the profile `box status` finds it on, by name across them all. `box list` lists every profile your blocks name, serve's own first (another's failing is said in one line, `<profile>: its boxes not listed: <why>`), and a box by name goes to the profile it was listed or made on. Each profile's AWS is made once. `$ABE_BOX_PROFILE` in serve's environment still pins one profile everywhere. The Layer a launch hands its box has no `checkouts:`, which hold this Mac's paths: its checkout's block is applied first, its paths (`org.dir`, `board.azureConfigDir`) left out. No token is ever handed.

Considered: a Layer per checkout (a sixth Layer between repo and yours) would change the Layer order that ADR 0011 fixes, and every `explain` and Settings source with it. Keys per checkout spread over the existing settings (`github.account.<path>`) would not merge as one value. A block in your own file keeps the order, keeps it yours, and lists one checkout's identity in one place.

Hard to reverse: the file shape is the person's, written by `--here`. Moving to another shape later means reading this one.

2026-10-27: in local mode a session gets no `GH_TOKEN` from `github.account`. Abe reads GitHub for it, and a repo script the session runs cannot write GitHub as that login.

Superseded in part by ADR 0030, 28 Oct 2026: the `checkouts:` blocks are no longer read; their values live in each repo's `.abe/settings.local.yaml`, and `org.dir` and `team` are retired.
