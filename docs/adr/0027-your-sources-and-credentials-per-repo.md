# 0027 · Your sources and credentials per repo

Status: accepted, 27 Oct 2026; its credentials part superseded by ADR 0028, its sources part by ADR 0031. Adds to ADR 0025 (who you are per checkout) and ADR 0011 (the Factory install).

A card session in a work repo could not read Sentry or Figma, and the app could not start. The MCP server the person added by hand was Claude Code local scope, keyed by the main checkout's path, and a card's worktree is another path. Abe passed `~/.claude.json` itself as `--mcp-config`, which loads only its top-level, user-scope `mcpServers`, so a local-scope server never reached a worktree. The app's aws profile and env file had no place at all: a session got nothing, or would have read the values itself.

**Credentials and the TEST yes are yours, per checkout.** ADR 0025's block takes two more keys: `credentials` (each environment's `awsProfile` and `envFile`, names and paths only) and `testWrites` (your yes to writes to the repo's TEST backends, from the Factory's Verify alone). A folder in the checkout, a card worktree beside it and a linked worktree of it all get the same values; a sibling checkout gets none. A shared Layer writing either is refused `personal-only`. In your own Layer outside a block either is `checkout-only` and never in force, so one repo's credentials never apply to another. Neither is handed to a box: they are this Mac's paths and profiles. An env file is a path in the main checkout or from `/`, never out of it with `..`. Values are never in a Layer, a record or a session: Abe injects exactly the picked set into the app and the checks, and sessions only see key names.

**Source servers live in the main checkout, as Claude Code local scope.** The install's Sources stage adds each server with `claude mcp add --scope local` run in the main checkout (`~/.claude.json` `projects[<main>].mcpServers`), never a tracked file. A server the person added there by hand is a source with no change. A card or linked worktree session's serve resolves its main checkout and writes an Abe-generated MCP config holding those of that checkout's local servers whose check at the install passed (connected, its one read ok), never an unchecked one: one not signed in, down, or stalling would hold the session's `claude` before its first hook. An install's session before Sources is done gets none. An unchecked source is told as not checked at install. Every session's `claude` gets `MCP_TIMEOUT` 15 s (Claude Code's server start timeout), so a server that stalls anyway gives up inside serve's 60 s wait for the first hook. The servers go with the same name, URL and headers, so Claude Code's stored sign-in is reused (it is keyed by name and definition, not by folder or scope). The generated file is in the session's own folder (mode 600, outside every sandbox's read set) and goes when the session ends. A definition holding a literal header or env value is not copied: Abe writes no second copy of a secret, and that server is told as not loaded. `--strict-mcp-config` stays, so claude.ai connectors never load in card sessions and do not count as a source there.

Abe never runs `claude mcp remove` on a source: it deletes the token every session shares. One name never gets two definitions: Claude Code's needs-auth cache is keyed by name, and the other definition would skip connecting for minutes.

Considered: a `sources` key in your Layer, keyed by repo. It would hold a second definition beside the one the person's own Claude Code already has for the main checkout, and the two can drift apart, which signs one out. The main checkout's own local scope is where Claude Code and the person already keep it.

Hard to reverse: the block's shape is written by the install and by `--here`, and the local-scope servers are the person's own Claude Code config.

Superseded in part by ADR 0030, 28 Oct 2026: `credentials` and `testWrites` are yours for the repo, in `.abe/settings.local.yaml`, not your own Layer's block for the checkout.

Superseded in part by ADR 0031, 28 Oct 2026: the source servers are the team's `sources:` in the repo's `abe.yaml` (name, transport, URL or command; never a secret), not Claude Code's local scope; every session's generated config is built from them. Abe still never runs `claude mcp remove`.
