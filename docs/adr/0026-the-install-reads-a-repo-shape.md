# 0026 · The install reads a repo's shape, and its stages branch on it

Status: accepted, 27 Oct 2026. Adds to ADR 0011 (the Factory install).

The install assumed every repo is a web app. On a tenant config repo (an identity provider's config as code, deployed by CI on every push to main, dev then test then prod) Read found four files, Run locally forced a running app and a URL gate onto it, Checks found nothing, and a team Layer's `autoMerge` would have let a green pull request deploy prod with no person. A CDK infrastructure repo went the same way: the session invented an HTTP harness around one function to pass the gate.

Read now gives the repo a shape from evidence (`core/src/install/install-shape.ts`): web app, service / API, config as code, infrastructure as code, library, CLI, or a monorepo of these with a shape per workspace. Each shape names the files that say so: a tenant file and a deploy tool CI runs (`a0deploy`), config templates and their `##KEY##` placeholders, `cdk.json`, `*.tf`, a Helm chart, a Dockerfile's `EXPOSE`, a web or server framework in the dependencies, `bin`, `main` / `exports`. Infrastructure files win over a deploy tool a Dockerfile only installs. A part with its stack beside code that runs (a `src/`, handlers, a server, a function's entry) is a service; it is infrastructure as code only when it holds the stack alone. Read also lists the deploy tools, the outside systems the dependencies and key names name (Auth0, SendGrid, Sentry), fixed ports, each environment's mapping file and the placeholders it does not map, and the paths it never reads (`cdk.context.json`, `cdk.out`, Terraform state and variable files, a rendered config, an env file). Only names and key names are kept.

Read also finds what a merge deploys (`core/src/install/install-deploys.ts`): the CI jobs that run on a push to the default branch (`main` or `master`, Read sees no remote) and deploy, each with its environment (`environment:`, else the word its name says) and whether it is prod.

The stages by shape:

| Shape                  | Run locally                                            | Verify                                                                                                        | Checks                                                                                      |
| ---------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| web app                | start on localhost, the URL gate                       | the app's pages in the browser                                                                                | CI's tests, types, lint                                                                     |
| service / API          | start on localhost, the URL gate                       | its endpoints answered                                                                                        | CI's tests, types, lint                                                                     |
| config as code         | nothing to run here: done at once, no scripts, no gate | static checks and the diff read; what only the deployed system runs is said, not run                          | static: `node --check`, JSON and YAML parse, placeholders mapped in each environment's file |
| infrastructure as code | nothing to run here                                    | static only: types, unit tests that need no synth, `terraform fmt -check`; never synth, plan, deploy or apply | static: those, YAML parse, Helm lint                                                        |
| library                | nothing to run here                                    | its tests and its build                                                                                       | CI's                                                                                        |
| CLI                    | nothing to run here                                    | the CLI on test input, its tests                                                                              | CI's                                                                                        |
| monorepo               | runs when one workspace is a web app or service        | each part's own                                                                                               | each part's                                                                                 |
| not known              | as an app, the gate                                    | the app                                                                                                       | CI's                                                                                        |

The static checks are written as repo checks (`checks:` commands) that need no secret and no network. JSON and YAML are parsed by Abe itself, `abe check json|yaml <files…>` (read-only, exit 1 at the first file that does not parse, its `file:line:column`; the `abe` client answers it alone, no serve, so it runs on a box or with serve down), so a check needs no ruby, python or YAML package on the machine. A check that fails on a clean main is not written (it would block every card): the person is told it as a finding. Read runs each static check that executes none of the repo's code (parses, placeholders, `terraform fmt`, `helm lint`; not types or tests) once on a clean tree of HEAD, outside the working tree, and drops the failing ones into `failing` with what they printed; types and tests are run by the Checks session in its sandbox. A JSON template that is not JSON until rendered is left out of the parse.

When a merge deploys, Board asks who merges before anything else (`ask: auto-merge`): "A merge here deploys dev, test, prod: who merges?", `A person merges` first. Only the person answers auto merge; a session may record the safe answer. Board ends only once the repo's own Layer says `autoMerge` as answered (`auto-merge-unwritten` otherwise), so a team Layer's value never carries in silently. Status, the Read and Board pages and Done say what a merge deploys.

A shape Read reads wrong is the person's to fix, at any stage before Done: `abe install answer shape <shape>` (Shape is wrong on the Read page; refused `only-you` from a session). Read reads again with it over the files' evidence, the answer is kept across rounds, and the stages follow it. A different shape takes back every stage from Checks on (its static checks, its testing skill, what Run locally and Verify do); the same shape said again moves nothing.

Considered: asking the person the shape at Read. Most repos say it plainly in their files; asking would add a question to every install. A "Go on without running it" answer at a gate that cannot start the app (R2-3) is the fallback for a shape Read takes for an app; the shape is the up-front answer.

Hard to reverse: the stage flow branches on the shape, and records keep the person's who-merges answer across rounds. A shape Read misreads makes Run locally pass with nothing run, so its evidence is shown wherever the shape is.

Amended by ADR 0040, 2 Nov 2026: "shape" is renamed "kind" (the repo's kind; `install-kind.ts`, `read.kind`, `abe install kind`, `web` read as `web-app`); this record keeps the old word as history. The person's correction is `kind:` in `abe.yaml`, the team's (one kind, or a monorepo's per part), read before the record's (`shapeSaid` read as `kindSaid`).
