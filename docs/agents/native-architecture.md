# Native architecture and verification

The architecture decisions live in root `docs/adr/`; vocabulary lives in `GLOSSARY.md`. This file locates the native implementation and its verification seams.

## Editor and surfaces

Rust draws chrome and owns Git data, terminal IO and native key routing. Neovim supplies editing, Vim modes, LSP, treesitter and engine state. `nvim --embed` starts with `vim.g.vimstorm_app`; plain `nvim` returns before app plugins. Runtime paths use the platform configuration/data/state roots.

`app/src/shell` composes tree/editor/bottom islands. `shell/layout.rs` maps Neovim grids to native pixel rectangles; keep rendering, hit testing and resize coordinates aligned. Managed workspaces reserve the rail (`Panels::rail`) and the header row (`Frame::with_workspace_strip`, the old strip's room) without moving native toolbar/status geometry.

Lua calls `config.app.bridge.notify(surface, payload)`; Rust decodes through `app/src/nvim/lua` and each surface's `on_lua`. Rust engine actions use `lua::call` into `config.app.<surface>`. A move (a file opened, a tab or split picked, a hosted tool window given the keys) uses `lua::navigate` (`SurfaceCx::navigate`) instead: `config/app/normal.lua` gets Neovim to Normal mode first (an open `/` or `:` line cancelled as Esc does, a pending operator dropped, Insert / Visual left; a blocking prompt gets Esc from `Rpc::unblock`), then moves, and a move that fails is a balloon; the keys that act anywhere get the same from the command line and with an operator pending (`config/webstorm.lua`, `normal.again`). Lua draws no duplicate chrome. `config/focus.lua` and `config.app.native_focus` coordinate focus; `config/bottom.lua` shares bottom space among native tools.

**Exactly one thing has the keys, and only it looks it** (2.2 on). While a layer is up (Command mode, a menu, a dialog such as Settings, a pick) the layer has them; else the island whose surface has GPUI focus (the Board, the Chat column, Boxes or Pipelines, the Editor and its pages). The one with the keys draws active (the blue tab box, the Board's blue ring and `Mine` tab, the composer's caret and border); everything else draws inactive grey, a slot's screen under a layer too. The bridge tells each slot's screen `focus true` only while no layer is up and the app says that slot has the keyboard (`serve/src/process/bridge.ts` `keysAt`); Rust's island headers use `editor::window_active` (a shot window counts as active) with their own `contains_focused`, and the Abe view and its slot views tell the bridge where the keyboard is from what each frame draws (no focus event comes in an inactive window).

- `app/src/shell/tree`, `shell/toolbar`, `app/src/editor/tabs`, `editor/statusbar`, `editor/floats`, `app/src/popups`, `app/src/search`: native editor surfaces.
- `app/src/editor/minimap`: VS Code's minimap (`editor.minimap`, on with Feel vscode), a layer right of each code split's grid (`WinRect::minimap`, the room the layout leaves); its slider from nvim's `win_viewport`, its lines from `config/app/minimap.lua`, which only reports data (the app asks `want` for the span shown, Lua answers `lines`).
- `app/src/editor/replace`: the ⌘R replace bar (fields, keys, toggles, buttons); `config/replace.lua` keeps its engine (matches, count, replacing), bridge `config/app/replace.lua`.
- `app/src/git` (data), `git/window`, `git/diff`, `git/annotate`; `nvim/lua/git`: data, native Git and actual Neovim diff/merge.
- `app/src/terminal`: the bottom panel's Terminal: the workspace's shells over one host nvim window (role `terminal`, `HostedFocus`), real VT parsing, selection and input; `terminal::open` is the one way in (the page, ⌘T, ⌃\`, the bridge's `terminal-tab`).
- `app/src/factory`: the Abe view (2.0 shell bridge): spawns `abe ui bridge` (`$ABE_BIN` or the `abe` beside the binary) through the bridge session (`factory/bridge`: the process, what the bridge is to know and its replay on a restart, frames decoded off the UI thread, where a slot's keyed `patch` is applied to the tree its reader holds (ADR 0036) and asked `again` when it does not apply; its table test runs on an in-memory pair, no GPUI), draws its component trees (closed set; contract and fixtures in `abe/packages/ui/contract`, read by `tests/contract.rs`) and forwards keys / clicks; Chat's transcript is a view of its own (`factory/transcript/view.rs`, cached: gpui draws it anew whenever a cached view around it is) that draws only the rows in and near its view, the rest standing in at their heights, a row never drawn at its estimate, so a session's first frame draws near its end (`transcript/window.rs`; every row while text is selected in it); the status line and the working dots are a view of their own the slot's host draws over it (`factory/status.rs` `Live`, `SlotView::hosted`), so their clock and pulse never draw the slot, and the `/` menu paints deferred over them; the bridge's shell effects run in `shell/effects.rs`; ⌘⌥A is the Board and back (`Projects::board_toggle`). Boxes and Pipelines (the `pane` slot, `factory/pipelines.rs`) and the Git Log's PR review (`factory/review.rs`, drawn by `git/window/review.rs`) are bridge slots too; the terminal component's PTYs are `factory/terminal.rs`. The Run page is the main slot's `run` screen, drawn by `factory/run.rs`, the Card page its `card` screen (`pages.rs` `CARD_SCREEN`), which ⏎ on a Board card opens in the `popup` slot instead, drawn over the dimmed Board (`factory/dialog.rs` `card_popup`); `Projects::show_page` opens both, their expand is the main area's ⌥⌘⏎ (`shell/projects/maximize.rs`).
- `:` is Command mode (with no `abe`, a line naming `./install.sh`).
- `app/src/shell/remote/mod.rs`: a box workspace's Neovim, shells, git, tree listings and picker previews through `abe workspace attach-spec`'s argv (ADR 0021); `shell/remote/link.rs` its RemoteState and status sign.
- `app/src/app/instance.rs`: native single-instance socket (`vimstorm <path>` hands the path to the running app).

`config/menu.lua` registers native context actions. Text a menu only says is an info line (`{ info = "…" }`, Rust `MenuEntry::Info`), never a disabled item; a list popup's long title wraps. New actions need both mouse and keyboard access. Editor tabs belong to their split. Preserve native selection, counts, tree search and Git list actions.

Theme sources are `app/src/look/theme.rs`, `nvim/lua/darcula.lua` and `nvim/colors/darcula-contrast.lua`. WebStorm scheme references can be read from its installed app jars when exact values are needed. Icons use existing WebStorm assets/font; plugins are pinned by `nvim/lazy-lock.json`.

## Testing seams

Use shared helpers: `app/tests/common/gitfix.rs`, `gitui.rs`, `bridge.rs` (the contract fixtures and a fake `abe ui bridge`), `view.rs`.

1. Abe's rules, commands and ports are tested in `abe/` (`cli()`, `scenario()`, fake `gh`, `claude`, `aws` and Azure DevOps: `abe/packages/testing`, the fake Azure server `src/fake-ado`); the app's Abe tests draw contract trees from the fake bridge: `tests/contract.rs` (every tree draws whole, its clicks reach the bridge), `tests/factory_layout.rs` (sizes per component and width), `tests/factory_slots.rs` (the Terminal and slot views), `tests/shell_effects.rs` (what each shell effect does to the window) and `tests/chat_column.rs`.
2. Git tests use real temporary Git. GPUI tests drive real key/mouse/IME events against embedded Neovim. Existing suites include projects, input, terminal, surface_keys, Git/diff and Abe flows.
3. Real Git/Neovim review tests exercise native diffs, comments, pending reviews and merge tools.
4. Small authorized live provider proofs establish capabilities fakes cannot prove. Record version, account, exact fixture/revision and limitations.

`tests/run.sh` isolates Lua tests and plugin state. Use `H.keys`, `H.gkey`, `H.lua`, `H.call`, `H.bridge`, `H.expect`/`H.wait_for`, and real files. Wait for observable conditions rather than fixed sleeps. `H.stop` catches messages/errors and blocking prompts. `k/l/ö/ä` follow this repo's keymap; `h/j` do not stand in for navigation.

For tests adding engine behavior, use the matching existing `*_test.lua` suite or a focused public engine module suite included in `run.sh`. Lua tests inspect engine/bridge state; Cargo tests inspect pixels, focus and native UI. Screenshots support visual QA and do not substitute for interaction tests.

Offscreen screenshots use `VIMSTORM_SHOT`, `VIMSTORM_WINDOW_SIZE` and `--features shots`. Isolate Abe configuration too: XDG isolation alone does not select `~/.config/abe`. A live offscreen app driven step by step (several at once, no OS keystrokes): the drive socket and `qarig`, [in-app QA](in-app-qa.md).
