# VimStorm: notes for contributors and their agents

A native macOS editor (Rust + GPUI, `app/`) around an embedded Neovim (`nvim/`), with Abe 3.x (TypeScript, `abe/`) inside it: Abe view (Board, Run), Abe chat, Chat, Sessions, Boxes, Settings, Command mode.

## Rules for the window

- Model the editor on WebStorm: same keys, behaviour, Islands Dark / Darcula Contrast colors. Preserve the editor, tree, LSP, search, Git, diff / merge and terminal.
- Keys: `k/l/ö/ä` = left/up/down/right. Keys live in [docs/reference/keys.md](docs/reference/keys.md): update it when visible keys change.
- Popup pickers, dropdowns and menus that filter type every letter; arrows, Ctrl-n and Ctrl-p move there. Lists with explicit search (tree, Git, switcher, Board) search only after `/`. Command mode's `:` line is the one exception (every letter types). Text fields, terminals and IME take their own text; Cmd+Enter keeps a field's own submit.
- Every native action also gets a mouse / context-menu route. Text a menu only says is `MenuEntry::Info` (Lua `{ info = … }`), never a grey item.
- Code is the main surface. The rail (left edge) picks tiles: Abe (the main checkout, first), a workspace per card, +, then Board, Boxes, Pipelines (⌘↑ / ⌘↓, ⌘← the Board, ⌘→ into the card's workspace, ⌘§ Abe); every move lands with the keys where they were as the tile (a workspace: its page) was left, Chat or the page (a first visit: Chat), kept in `rail-memory.json`. A workspace's header row picks its page, kept per workspace: Code, Run, Card (⌃1–⌃3). Code has a bottom panel (Terminal · Git · Problems; shown, tab and height kept per workspace). Pane keys toggle as WebStorm's tool-window keys (`shell/pane_key.rs`): closed → shown with the keys, shown → the keys, focused → hidden, the keys back: ⌘1 the page's left pane (off Code: focus only), ⌘3 the bottom panel's Git, ⌘T its Terminal (each over another tab: switched to it), ⌘4 Chat; ⌘2 the main pane (focus only), ⌘J panel shown / hidden; ⌃⌘← / ⌃⌘→ Chat / Claude Code (on Code with the keys outside Chat: that pane's tabs); ⌥⌘← / ⌥⌘→ the focused pane's tabs. Chat column = right island on every tile, the AI chat only (Chat mode default; Terminal mode is the session's Claude Code). Sessions is a Board tab. Attention is quiet: tile dots, "N need you"; no banners, bells or dock badge.
- Gone, keep them gone: the Terminal and Git pages, ⌘5–⌘9, ⌃W, the workspace strip and the window's stripe (the rail; Welcome keeps a stripe), the Inbox, the ask bar `i`, the right chat, the `g` jumps in Abe's screens (`gg` / `G` stay), ⌃⌘⏎ maximize, CtrlCmdK, lanes.
- A new colour const is named after its DS token, else gets a `look::FOLLOWS` row (`app/tests/theme.rs` checks).
- Work starts only from Azure stories; GitHub tracks specs and dependencies, readiness is informational (ADR 0006). Agents never merge; the human merge is confirmed and bound to the reviewed head.

## Where things live

- Abe 3.x screens are drawn by `app/src/factory/*` (and `app/src/git/window/review.rs`) from `abe ui bridge` component trees. Their read-only words go through `select::text` (`factory/select.rs`, a story's markdown through `TextSel::selectable`) so the mouse selects and ⌘C copies them; buttons, key hints, glyphs and hover text stay plain. Before adding a command, port or test in `abe/`, read [docs/reference/abe.md](docs/reference/abe.md) (packages, import rules, harness).
- Native editor, window shell, focus, bridge, test seams: `docs/agents/native-architecture.md`.
- Sessions are Claude Code's, owned by `abe serve` (ADR 0020). The 1.x Rust Abe (its window, `abe-core` / `abe-ports` crates) is gone: `app/` is one crate; Delete Working Files and a folder's main checkout are `app/src/git/worktree.rs`.
- Keep IO off the UI thread; use the existing state / effect runner and provider adapters; closed enums and typed calls across seams. Runtime data in platform state paths; keep unknown config fields; restoration never relaunches work or replays prompts. Clear token overrides from children.

## Verification

- TypeScript (`abe/`): strict, zod at every edge, no `any`; a type assertion only behind a commented eslint-disable. Run `bun test <path>`, `bun run typecheck`, `bun run lint`. Use the real node (a shell without `VOLTA_HOME` can make volta's shim fork forever).
- Rust: bounded builds (`CARGO_BUILD_JOBS=4 RUST_TEST_THREADS=2` or the serial runner), each worktree its own `CARGO_TARGET_DIR`. Window tests: `app/tests` (helpers `tests/common/{view,bridge,gitfix}.rs`; Abe screens from the contract trees `abe/packages/ui/contract` and the fake bridge). Targeted: `cargo test --test app tree::` (also `--test perf`, `--test theme`; app/README.md).
- Full checks: in `app/` `cargo test`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo fmt --check`; `tests/run.sh`; `bun run check` in `abe/`.
- A fix adds a row to the module's existing table test, never a new file, an issue-named test or a copy in another layer. Sweeping a folder, each test file is kept, folded into the table at its module's interface or deleted once another test covering it is named ([Abe reference § Tests](docs/reference/abe.md#tests)). Inside `abe/` packages a folder is a module: other folders import only its interface, listed in `packages/<package>/folders.ts` (ADR 0024). No issue numbers in comments, test names or docs; `abe/` serve tests go in-process (`served()` / `scenario()`), `cli()` only for a command's contract ([Abe reference § Tests](docs/reference/abe.md#tests); reviewers check it).
- Tests use fake ports, disposable fixtures and isolated state, never the user's live Abe settings or real setup tools. Any run of the app or `abe serve` gets its own `XDG_STATE_HOME`, `ABE_STATE_DIR` / `ABE_CONFIG_DIR` and `VIMSTORM_NO_INSTANCE=1`; a test starting the binary also sets `VIMSTORM_CONFIG_HOME`. Leave the installed app and the user's running projects alone. Visual QA: `shots` (app/README.md); in-app QA drives offscreen apps over the drive socket, never OS keystrokes ([in-app QA](docs/agents/in-app-qa.md)).

## Commits and tracking

One line `<Summary>. (#N)` (the issue's number when there is one), no trailers, no amend. Preserve unrelated work. Agents never merge: a human reviews and merges. Issues are this repo's GitHub issues ([issue tracker](docs/agents/issue-tracker.md), [domain](docs/agents/domain.md), [labels](docs/agents/triage-labels.md)).
